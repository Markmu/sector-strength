## 二、实现规格逐项复核（重点项）

### 1. 五字段全行求和与 rzrqye 重算（不读行内 rzrqye）— 符合

`_aggregate()`（margin_service.py:194-223）仅对 `MARGIN_SUM_FIELDS = (rzye, rqye, rzmre, rzche, rqmcl)` 五字段累加（行数以 `get_margin` 实际返回为准，兼容三行/两行/一行）；`totals["rzrqye"] = totals["rzye"] + totals["rqye"]` 服务层重算，循环体从不读取 `row["rzrqye"]`——与 spec D2 冻结口径一致。各结果 `quantize(Decimal("0.01"), ROUND_HALF_UP)` 对齐 Numeric(20,2)。全 Decimal 累加，无 binary float。

AC-1 数值验证（三行求和）：

- rzye = 1.0E12 + 8.0E11 + 2.0E10 = **1.82E12** ✓
- rqye = 5.0E10 + 3.0E10 + 1.0E10 = **9.0E10** ✓
- rzmre = 7.0E10 + 4.0E10 + 1.0E10 = **1.2E11** ✓
- rzrqye = 1.82E12 + 9.0E10 = **1.91E12**（重算值）✓

与 2026-08-14 人工裁定后的 plan-03 §5 期望值逐一相符（`test_sync_date_aggregates_all_exchange_rows` 落库断言）。

### 2. on_conflict_do_update 显式 updated_at=func.now() — 符合

`_atomic_upsert()`（margin_service.py:225-271）与 16 期 `market_metrics_service.py:805-855` 范式逐行一致：`update_cols` 先取六指标 `stmt.excluded` 列，再显式追加 `update_cols["updated_at"] = func.now()`，最后 `on_conflict_do_update(index_elements=["trade_date"], set_=update_cols)`。AC-2 测试以 `asyncio.sleep(0.01)` 保证时间戳可区分后断言 `row.updated_at > first_updated_at`，覆盖该 16 期 S1 教训点。

### 3. task_context 先 lock_and_validate 再 upsert — 符合

`_atomic_upsert` 中 `task_context is not None` 时先 `await task_context.lock_and_validate(self.session)`（同一 session，同事务），再执行 pg_insert。`TaskFenceContext` 为 `TYPE_CHECKING` 前向引用 + `from __future__ import annotations`，运行时不导入（16 期 task_fence.py L103/L121 协议已存在）。测试 `test_task_context_lock_and_validate_invoked_before_upsert` 以记录型 `execute` 包装断言事件序 `["lock_and_validate", "upsert"]` 并验证传入 session 同一；`test_task_context_fence_validation_failure_rolls_back` 验证 `FenceValidationError` → 当日整体回滚不落库。

### 4. commit/rollback 语义 — 符合

成功路径 `execute → commit`；`except Exception: await self.session.rollback(); raise` 透传（当日不留半成品）。测试覆盖 upsert 阶段 DB 异常（表级 execute 注入 RuntimeError）与聚合阶段失败（非 Decimal 字段）两类，均断言表无新行。

### 5. 日历守卫零 Provider 调用 — 符合

守卫顺序为 `TradingCalendarRepository.get_record(T)` → 无记录抛 `MarginSyncError`（拒绝自然日/工作日猜测）→ `not is_open` 返回 `"skipped"`，均发生在 `get_margin` 之前。测试断言休市日 `fake.get_margin_call_count == 0`、无记录日 `call_count == 0`（守卫在拉取前短路），对应"休市日不浪费积分配额"的风险备注。

### 6. 其余规格点

- 日历守卫结构、`get_margin` 同步调用（无 await，与 plan-02 `def get_margin(...) -> List[dict]` 签名一致）、空结果抛错、交易所护栏（缺 SSE/SZSE 记 WARNING 含交易所集合后继续，`_REQUIRED_EXCHANGES = {"SSE", "SZSE"}`，BSE 缺席不告警）、结构化日志（trade_date/exchange_count/row_count/rzrqye/duration_ms/status）均符合 §3 规格。
- "不在范围"核查：未实现 AsyncTask 编排、admin 端点、查询 API；未创建 margin_repository.py（裁定 service 内直查）——无越界。
- 防御性增强：`_aggregate` 对非 Decimal 字段抛错（plan-02 已有 Decimal 强约束，此处双保险，"宁失败不猜测"），属合理护栏非越界。
