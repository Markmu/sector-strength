# 04-0 需求设计：A 股基金持仓分析

## 0. 文档说明

**产品核心目标**：为个人投资者提供 A 股市场全部基金（场内 ETF + 场外开放式）的最新与历史持仓明细，支持按基金搜索与按持仓股票反查，让用户能"看见谁在买我关注的股票"以及"我想买的基金都重仓了什么"。

**本需求定位**：
- **上期基础**：sector-strength 已有板块强度、个股均线等行情分析能力，数据流以"日 K + 均线 + 强度"为主线。
- **本期做什么**：在现有"行情分析"基础上，新增独立的"基金持仓分析"模块，补齐"机构资金动向"这一观察维度。
- **阶段定位**：MVP 首版。目标是把"基金基本信息 + 持仓明细 + 双向搜索"三个最小闭环跑通，不做实时净值计算、不做变动提醒、不做历史多期对比图表。

**相关文档**：
- 01 需求设计：自动数据质检与每日拉取补全
- 02 需求设计：数据状态总览与一键补齐
- 03 需求设计：数据源替换 Tushare

## 第一部分 需求分析与确认

### 1.1 项目背景

sector-strength 当前能为个人投资者展示股票与板块的日 K、均线、强度等行情指标，但在"机构资金动向"这一维度上仍是空白。一个常见的个人投资者困惑是："我看好贵州茅台，机构和明星基金最近还在加仓吗？"——目前用户必须去第三方平台逐家翻看季报，无法在站内一次性回答。

**具体问题**：

1. **"基金 → 持仓"无入口**：站内没有任何基金列表，更没有"这只基金最新一期重仓了哪些股票"的能力。
2. **"股票 → 哪些基金重仓"无入口**：用户无法回答"我关注的股票，最近一期有哪些基金重仓持有"。
3. **数据没有沉淀**：即便临时通过第三方查到一次，下次又得重新查；站内的所有分析都基于行情，无法引入"持仓占比变化"作为辅证。
4. **数据源未明确**：与现有 Tushare 数据源习惯保持一致是项目长期约束，引入新数据源会带来双源对齐问题。

**本期目标（一句话）**：让用户能在站内通过一次搜索，获得某只基金的最新持仓明细，或通过股票反查得到"最近一期重仓持有该股的基金列表"。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|---|---|
| 想了解某只基金的最新持仓 | 需要跨多个第三方平台（基金公司官网、天天基金、东方财富）逐家翻季报 PDF |
| 想了解某只股票被哪些基金重仓 | 没有聚合视图，只能在搜索引擎拼凑，且常遇到数据滞后 |
| 想要对比多家基金的重仓股重叠度 | 没有横向对比入口，只能在多个窗口来回切 |
| 站内所有分析都缺"机构持仓"维度 | 行情分析停留在 K 线层面，无法交叉验证"资金面" |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---|---|---|---|
| 数据源 | 沿用现有 Tushare 数据源 | 与项目 03 决策一致，避免双源对齐 | 自建爬虫（合规与维护成本高） |
| 数据范围 | 全市场 A 股基金（场内 ETF + 场外开放式） | 覆盖"任意基金"和"任意股票"两个搜索入口 | 仅做 ETF（覆盖面不足） |
| 持仓数据时效 | 取最近一期已披露报告期 | 季报披露规则决定，强制实时无意义 | 实时估算（数据源不提供） |
| 数据采集方式 | 管理后台手动触发 + 后续可扩展为定时 | MVP 不引入调度复杂度 | 一开始就上自动调度（MVP 过重） |
| 搜索方向 | 双向：按基金搜 + 按股票反查 | 覆盖用户两类典型诉求 | 单向（只能按基金搜） |
| 详情页深度 | 列表 + 最新一期持仓明细 | MVP 闭环所需 | 历史多期走势 + 净值曲线（非本期） |
| 个别基金数据缺失 | 在列表和详情页标注"暂无持仓数据" | 实测发现 Tushare 收录不全属正常现象 | 隐藏缺失基金（造成用户疑惑） |

### 1.4 产品范围

**本期范围（必须交付）**：

- **基金基本信息库**：在站内展示全市场 A 股基金（场内 ETF + 场外开放式）的名称、类型、基金管理人、成立日期、跟踪标的（指数）等基本信息，便于用户一眼判断基金风格。
- **基金列表与搜索**：在仪表盘"基金分析"入口下提供基金列表，支持按基金代码、名称搜索，支持按"场内/场外"、"基金类型"过滤。
- **基金详情页**：点击某只基金后，展示其最新一期已披露报告期的持仓明细（按持仓占比从高到低排序）。
- **股票反查**：用户输入某只股票代码，可查看最近一期报告期"重仓持有该股"的基金列表。
- **管理端采集入口**：管理员可在管理后台手动触发一次"基金基本信息"或"持仓明细"的数据同步，看到同步结果（新增/更新/失败数量）。
- **数据缺失的透明呈现**：对 Tushare 未收录或当前期未披露的基金，列表与详情页均明确标注"暂无持仓数据"，不静默隐藏。

**明确不做**：

- 实时净值估算与基金日 K 线
- 持仓变动提醒（增减仓通知）
- 历史多期持仓变化趋势图
- 基金经理维度分析
- 持仓行业聚合与板块联动分析
- 自动化定时同步（首版仅手动）
- 用户自选基金 / 自选股票
- 第三方登录与社交分享

## 第二部分 用户旅程和用户故事

### 2.1 核心用户旅程

**主旅程：用户想了解"我关注的股票，机构和明星基金最近还在加仓吗"**

```
[进入基金分析]
   ↓
[1. 在仪表盘"基金分析"入口点击进入，进入基金列表页]
   ↓
[2. 在列表页顶部"按股票反查"搜索框输入关注的股票代码或名称，例如"600519"]
   ↓
[3. 系统跳转"反查页面"，展示"最新一期重仓持有贵州茅台的基金"列表]
   ↓
[4. 用户查看列表，看到"某明星基金持仓占比 5.2% / 持仓市值 12 亿"]
   ↓
[5. 用户点击某只基金，跳转"基金详情页"]
   ↓
[6. 详情页展示该基金基本信息 + 最新一期持仓明细（按占比降序）]
   ↓
[7. 用户对照自己关注的"另一只股票"是否也在持仓中，得出"机构持续看好"的判断]
```

**主旅程：用户想了解"我想买的 ETF 到底持仓什么"**

```
[1. 在基金列表搜索"沪深 300"或代码"510300"]
   ↓
[2. 列表筛选结果展示若干匹配项]
   ↓
[3. 用户点击"华泰柏瑞沪深 300ETF"]
   ↓
[4. 详情页展示基金基本信息 + 最新一期持仓（300+ 只成份股，按占比降序）]
   ↓
[5. 用户看到前 10 大重仓股，确认与自己看好的方向一致]
```

**主旅程：管理员同步基金数据**

```
[1. 管理员进入"管理 / 数据采集 / 基金"页面]
   ↓
[2. 点击"基金基本信息 / 手动同步"或选择报告期后点击"同步指定报告期"]
   ↓
[3. 按钮变为"同步中…"并禁用，页面展示进度提示]
   ↓
[4. 同步完成，页面展示"新增 X 条 / 更新 Y 条 / 失败 Z 条"统计]
   ↓
[5. 管理员在同步记录表中确认本次执行记录，返回基金列表验证数据已更新]
```

**异常旅程**：

- **数据缺失**：用户搜索某只基金后进入详情页，若 Tushare 未收录该基金持仓或当前期尚未披露，页面明示"暂无最新持仓数据，已展示基金基本信息"，并提供"返回列表"和"重新同步"按钮，避免用户误以为系统故障。
- **同步失败**：管理员点击"手动同步"后，若接口超时或返回异常，后台提示"同步失败，原因：xxx"，并保留上次成功的数据，列表与详情页可继续使用。
- **股票无任何基金重仓**：反查结果为空时，页面说明"在最新一期报告期，暂无基金披露重仓持有该股票"，避免用户怀疑系统遗漏。

### 2.2 用户故事

**核心用户故事**：

- **US-01**：作为个人投资者，我希望在站内搜索某只基金并查看其最新一期的重仓股，以便快速判断"这只基金的真实投向"是否符合我的偏好。
- **US-02**：作为个人投资者，我希望输入一只股票代码，看到"最新一期重仓持有该股的基金列表"以及各家持仓占比，以便判断"机构是否仍在加仓我关注的股票"。
- **US-03**：作为个人投资者，我希望从基金列表能按"场内 ETF"和"场外开放式"分类浏览，并按基金类型（股票型、混合型等）过滤，以便快速缩小候选范围。
- **US-04**：作为管理员，我希望在管理后台一键触发基金信息同步，并在同步完成后看到新增/更新/失败的统计，以便在数据缺失时主动补齐。

**延伸用户故事**：

- **US-05**：作为个人投资者，我希望在搜索结果中看到基金名称、代码、类型、管理人、成立日期、跟踪标的等关键信息，以便在不进入详情页的情况下快速判断基金风格并完成初步筛选。
- **US-06**：作为个人投资者，我希望在反查结果中能按持仓占比从高到低排序，以便优先关注重仓机构。

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |

| 列表加载中 | 表格区域显示骨架占位 | 等待加载完成 |
| 搜索无结果 | 表格区域显示"未找到匹配基金，请调整搜索词或清除过滤项" | 修改搜索词或清除过滤 |

### 3.3 业务规则

- **搜索匹配规则**：搜索框同时匹配"基金代码（含 .SH / .SZ / .OF 后缀）"和"基金名称（中文）"；代码按前缀匹配，名称按包含匹配；不区分大小写。
- **过滤规则**：可同时勾选"场内"和"场外"，也可多选基金类型；过滤项之间为"且"关系；过滤后列表与搜索词同时生效。
- **排序规则**：列表默认按基金代码升序；详情页持仓明细按"占净值比"从高到低排序；反查页结果按"占净值比"从高到低排序。
- **持仓明细展示规则**：默认展示前 20 条，点击"全部持仓"展开完整列表；持仓占比保留两位小数；港股 / 境外标的的"占流通比"字段为空白时显示"—"而非"0%"。
- **报告期选择规则**：详情页默认展示"最新一期已披露报告期"；不提供用户主动切换历史期（MVP 范围外）。
- **数据缺失标注规则**：当 Tushare 未收录某基金持仓或该期未披露时，详情页明示"暂无最新持仓数据"，并在列表页该基金所在行用浅色文字标注"暂无数据"，不静默隐藏。
- **反查阈值规则**：反查默认仅展示"占净值比 ≥ 1%"的基金，理由是低于此比例的"微持仓"对个人投资者判断机构动向价值有限；阈值在 MVP 阶段为固定值，不向用户暴露。
- **同步权限规则**：基金同步入口仅对管理员角色开放，普通用户在导航栏中看不到"管理 / 数据采集 / 基金"菜单。
- **货币与单位规则**：持仓市值统一以"元"为单位展示，超过亿时以"X.X 亿"形式呈现；持仓股数与占比保留原值不做单位换算。
- **跟踪标的展示规则**：列表页和详情页均展示基金跟踪标的（来自基金基本信息中的业绩比较基准/跟踪指数字段）；被动指数型基金展示指数名称（如"沪深 300 指数"），主动管理型基金若无可识别的单一跟踪指数则显示"—"。

## 第四部分 验收标准

- **AC-01：基金列表展示与搜索**
  前置：管理员已在管理后台完成"基金基本信息"同步。
  动作：用户在仪表盘"基金分析"入口进入基金列表页，输入"沪深 300"。
  结果：列表展示所有名称包含"沪深 300"的基金项，每项展示代码、名称、类型、跟踪标的、管理人、成立日期，点击任一项可进入详情页。

- **AC-02：基金过滤**
  前置：基金列表已加载。
  动作：用户勾选"场内 ETF"与"股票型"两个过滤项。
  结果：列表仅展示"市场 = 场内"且"基金类型 = 股票型"的基金，且过滤项与搜索词（如有）同时生效。
