# 用例详情：UC-012 - 补齐 API 409 冲突处理

**Case ID:** UC-012
**模块:** 数据状态标签页
**用例类型:** 异常
**优先级:** P1
**创建日期:** 2026-05-27
**关联验收标准:** AC-03

## 用例描述

验证同类型已有活跃任务时，点击补齐按钮后后端返回 409 冲突，前端按钮恢复可用。

## 前置条件

1. 以管理员身份登录系统
2. 某类数据有缺失且已有活跃的补齐任务（可通过两个浏览器窗口模拟）

## 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 在窗口 A 触发某类型补齐任务 | 任务创建成功，显示进度条 |
| 2 | 在窗口 B 打开同一页面 | 该类型卡片显示缺失态（因 active_task 被另一任务占用） |
| 3 | 在窗口 B 点击"补齐缺失数据" | 后端返回 409 错误 |
| 4 | 观察按钮状态 | 按钮恢复可用（不再禁用） |

## 预期结果

- 后端返回 409 { detail: "该类数据已有补齐任务正在执行" }
- 前端不崩溃，按钮恢复可用
- 控制台输出错误日志但不影响页面
