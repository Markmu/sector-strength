# 02-0 需求设计：数据状态总览与一键补齐

## 0. 文档说明

**产品核心目标**：让管理员一眼看清板块数据的时效性，快速补齐缺失数据

**本需求定位**：[现有数据管理页面的手动任务创建流程] + [新增数据状态总览卡片和按类型一键补齐操作] + [现有功能的体验增强]

**相关文档**：
- 01-0-需求设计-自动数据质检与每日拉取补全

---

## 第一部分：需求分析与确认

### 1.1 项目背景

当前数据管理页面提供板块历史数据、均线数据、强度数据的初始化和计算功能，管理员通过选择日期范围、点击按钮来创建任务。但页面上没有任何信息告诉管理员"数据目前是什么状态"——最新数据到哪一天、有没有缺口、哪些数据需要补齐。管理员需要凭记忆或手动查库才能判断，再回到页面选择日期范围手动触发补齐。

**存在的问题**：

- 看不到各类板块数据的最新日期和健康状态，无法快速判断数据是否需要维护
- 不知道缺失的具体日期范围，手动查日期再填参数容易遗漏或填错
- 每次补齐都要手选日期范围，重复操作多

**本期目标**：管理员打开数据管理页面，立即看到板块历史数据、均线数据、强度数据三类数据的状态卡片；发现缺口后，一键触发补齐，无需手动填写日期。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|---------|
| 不知道数据最新到哪一天 | 可能长期使用过期数据做分析而不知情 |
| 不知道哪些日期有缺口 | 缺口积累越来越多，补齐时需要手动排查 |
| 补齐操作需要手动填日期参数 | 选错日期范围导致重复拉取或遗漏 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 功能入口 | 在数据管理页面新增"数据状态"标签页 | 与现有数据管理功能在同一页面，上下文连贯 | 独立页面 — 多一次导航跳转，增加操作成本 |
| 缺失检测范围 | 只覆盖板块维度（历史数据、均线、强度）三类 | 用户明确限定范围，个股数据量过大且非当前维护重点 | 全部数据类型 — 信息过载，稀释关注点 |
| 补齐触发方式 | 每类数据独立的"补齐缺失"按钮 | 用户可按需选择补齐哪类数据，避免全量操作耗时过长 | 一个"全部补齐"按钮 — 耗时不可控，且部分数据可能无需补齐 |
| 补齐实现 | 复用现有任务系统 | 已有成熟的任务创建和进度跟踪机制，无需重复建设 | 重新实现同步逻辑 — 重复造轮子 |

### 1.4 产品范围

**本期范围**：

- 在数据管理页面新增"数据状态"标签页，作为默认展示
- 展示三类板块数据的最新日期、状态标记（正常/缺失）、缺失日期范围
- 每类数据提供独立的"补齐缺失"按钮，自动检测缺失日期范围并触发对应的补齐任务
- 补齐任务创建后，在状态卡片上显示任务进度
- 页面加载时自动获取最新状态

**明确不做**：

- 个股数据的状态展示和补齐
- 自动定时补齐（已有定时任务系统覆盖）
- 数据质量评分或健康度评分
- 历史补齐记录查看
- 数据记录数等统计信息展示

## 第二部分：用户旅程和用户故事

### 2.1 核心用户旅程

```
管理员打开数据管理页面
  → 看到"数据状态"标签页（默认）
  → 三类数据状态卡片同时展示
  → 查看每类数据的最新日期和状态

  情况 A：三类数据都正常（无缺失）
    → 无需操作，关闭页面

  情况 B：某类数据有缺失
    → 看到橙色缺失标记和缺失日期范围
    → 点击该类数据的"补齐缺失"按钮
    → 系统自动检测缺口并创建补齐任务
    → 卡片上显示任务进度
    → 任务完成后，状态自动刷新为正常
```

**异常旅程**：

- **补齐任务失败**：卡片上显示失败状态和错误信息，管理员可再次点击按钮重试
- **补齐任务进行中**：按钮变为禁用态，显示当前进度百分比，管理员可切换到其他标签页查看历史任务
- **状态获取失败**：卡片显示加载失败提示，提供"重试"链接

### 2.2 用户故事

**核心用户故事**：

- 作为管理员，我希望打开数据管理页面就能看到各类板块数据的最新日期和健康状态，以便快速判断是否需要维护
- 作为管理员，我希望看到有缺口时具体的缺失日期范围，以便了解缺口严重程度
- 作为管理员，我希望点击一个按钮就能自动补齐缺失数据，无需手动选择日期范围，以便减少操作步骤和出错概率

**延伸用户故事**：

- 作为管理员，我希望补齐任务创建后能看到进度，以便知道任务在正常执行
- 作为管理员，我希望任务完成后状态自动刷新，以便确认补齐是否成功

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
|------|---------|-----------|
| 加载中 | 三张卡片显示骨架屏/加载态 | 等待加载完成 |
| 正常 | 绿色"正常"标记，只显示最新日期 | 无需操作 |
| 缺失 | 橙色"缺失"标记，显示缺失日期范围 + "补齐缺失数据"按钮 | 点击按钮触发补齐 |
| 补齐中 | 按钮变为进度条 + 百分比，按钮禁用 | 等待完成或切换到其他标签 |
| 补齐失败 | 红色"失败"标记 + 错误提示 + "重新补齐"按钮 | 点击重试或排查原因 |
| 补齐成功 | 卡片刷新为正常态 | 无需操作 |

### 3.3 业务规则

- **最新日期判定**：取该类数据所有记录中最大的日期值，不区分板块个体差异
- **缺失判定**：最新日期之后的交易日（至当日）存在未覆盖的日期，即视为有缺口
- **缺失日期范围展示**：显示第一个缺失交易日和最后一个缺失交易日，格式为"YYYY-MM-DD ~ YYYY-MM-DD"
- **补齐按钮行为**：点击后自动以"最新日期的次日"为起点、"当日"为终点，创建对应类型的补齐任务
- **进度展示**：任务创建后，卡片内展示进度百分比，每 2 秒自动刷新任务状态
- **状态刷新时机**：页面首次加载时获取状态；任务完成（成功或失败）后自动刷新
- **按钮禁用规则**：补齐任务进行中时，该类数据的补齐按钮禁用，防止重复创建任务

## 第四部分：验收标准

- AC-01：数据状态展示
  前置：系统中有板块历史数据、均线数据、强度数据
  动作：管理员打开数据管理页面，进入"数据状态"标签页
  结果：页面显示三类数据的状态卡片，每张卡片显示数据类型名称、最新日期、状态标记（正常/缺失）

- AC-02：缺失检测与日期范围展示
  前置：板块均线数据的最新日期为 2026-05-23，今天是 2026-05-27，中间有交易日未被覆盖
  动作：管理员查看板块均线数据卡片
  结果：卡片显示橙色"缺失"标记，并展示具体的缺失日期范围（如"2026-05-24 ~ 2026-05-27"）

- AC-03：一键补齐触发
  前置：某类数据存在缺失
  动作：管理员点击该类数据的"补齐缺失数据"按钮
  结果：系统自动以最新日期次日为起点、当日为终点创建补齐任务，卡片显示进度条和百分比

- AC-04：补齐完成后状态刷新
  前置：补齐任务正在执行中
  动作：任务执行完成
  结果：卡片自动刷新为正常态（绿色标记，最新日期更新），进度条消失

- AC-05：补齐失败处理
  前置：补齐任务执行失败
  动作：管理员查看失败的数据卡片
  结果：卡片显示红色"失败"标记和错误信息，提供"重新补齐"按钮可重新触发

- AC-06：状态获取失败处理
  前置：页面加载时数据状态获取失败
  动作：管理员查看加载失败的卡片
  结果：卡片显示加载失败提示，提供"重试"链接可重新获取状态
