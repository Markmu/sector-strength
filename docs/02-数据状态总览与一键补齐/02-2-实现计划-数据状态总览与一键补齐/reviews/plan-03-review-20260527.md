## 上次 Blocker 修复验证

### Blocker #1: API 响应数据结构不匹配 — 已修复

**上次问题**: `useDataStatus` hook 的 SWR 泛型为 `DataTypeStatus[]`，与后端返回 `{ items: [...] }` 不匹配。

**修复方案**: `useDataStatus.ts` 已将 SWR 泛型改为 `useSWR<{ items: DataTypeStatus[] }>`，并从 `data?.items` 提取数组。`fetcher` 返回 `result.data || result`，后端返回 `{ success: true, data: { items: [...] } }`，经 fetcher 解包后 SWR 得到 `{ items: [...] }`，hook 正确提取 `.items` 字段。

**验证结果**: 通过。代码逻辑与数据流一致。

### Blocker #2: active_task failed 状态后端不返回 — 已修复

**上次问题**: 后端 `_get_active_task` 只查询 `pending`/`running`，前端实现了 `failed` 场景渲染但后端不返回。

**修复方案**: `data_status.py` 的 `_get_active_task` 查询条件已扩展为 `AsyncTask.status.in_(["pending", "running", "failed"])`，包含 `failed` 状态任务。

**验证结果**: 通过。后端现在会返回最近一次 `failed` 任务信息供前端渲染。

### Mock 同步

`mock-api.ts` 的 `DataStatusResponse` 接口已更新为 `{ success: boolean, data: { items: DataTypeStatus[] } }`，mock 返回格式与真实 API 一致。
