# UC-012 UAT 发现：次要缺陷记录（非阻塞）

**用例：** UC-012（管理员手动触发当日采集）
**发现时间：** 2026-07-30 UAT 第 1 轮

## 发现 1：基础信息同步跨 event loop 错误（轻微）

**摘要：** sync_etf_basic 写入基础信息时，1 条 ETF（561620.SH）写入失败，报错 `Future attached to a different loop`。

**日志：**
```
WARNING - 写入 ETF 基础信息 561620.SH 失败: Task got Future attached to a different loop
[ETF] 基础信息同步完成: 总计 1806, 入库 1805, 失败 1
```

**影响：** 1806 条中仅 1 条失败（0.05%），不影响整体功能。根因是 task_executor 后台引擎与 collector 的 event loop 不一致。非阻塞，可作为后续优化项。

## 发现 2：行业指数归类规则覆盖不足（对应架构 Q1）

**摘要：** EtfIndexClassifier 对行业主题指数的归类覆盖率不足，大量行业 ETF 被归入 category=other。

**日志（归类失败样本）：**
```
[ETF] 归类失败（category=other）共记录中样本 20 条:
- 中证全指食品指数、中证云计算50指数、中证金融科技主题指数
- 国证价值100指数、中证全指红利质量指数、中证畜牧养殖产业指数
- 标普中国A股大盘红利低波50指数 ...
```

**影响：** 这些行业 ETF 被归入 other，无法在"行业"维度按指数聚合展示（UC-002 行业维度返回空）。这正是架构文档 Q1 标注的开放问题（"行业指数数量多，规则覆盖率需实测"），UAT 实测确认了覆盖率不足。

**建议：** 扩展 EtfIndexClassifier 的行业关键词规则（覆盖"中证XX主题/产业""国证XX""标普中国A股XX"等模式），或对 benchmark 提取的指数名做更宽松的行业匹配。这是归类规则迭代问题，不影响宽基（宽基 100% 命中）和采集写入。

## 结论

UC-012 核心采集链路（任务触发→执行→落库）工作正常（task status=completed），份额采集的日期格式 bug 已修复（见 UC-014 证据）。这两个次要发现非阻塞，归类覆盖率待规则迭代。
