# UC-014 / UC-012 UAT 缺陷证据：fund_share 日期格式 bug

**用例：** UC-014（管理员按日期初始化历史数据）/ UC-012（管理员手动触发当日采集）
**状态：** 缺陷已发现并修复，复验中
**发现时间：** 2026-07-30 UAT 第 1 轮

## 失败/问题摘要

历史回填触发后任务秒级完成，但 etf_daily 表未写入真实 ETF 份额数据（仍为 mock 残留的 3 条），根因是 `sync_etf_daily` 调用 `get_fund_share(trade_date)` 时传入了带横杠的 ISO 日期格式（`2026-07-29`），而 Tushare fund_share 接口只接受无横杠的 `YYYYMMDD` 格式（`20260729`），导致返回 0 条数据。

## 执行日志（关键证据）

回填任务日志显示份额采集返回 0：
```
[INFO] [0/1] 正在拉取 ETF 当日份额 (trade_date=2026-07-29)...
[INFO] [0/0] 共 0 条 ETF 份额待处理
[INFO] [0/0] ETF 当日采集完成: 处理 0, 跳过 0, 净值缺失 0
```

日期格式对比实测（Tushare fund_share 接口）：
```
trade_date='20260729':  返回 1695 条, code=0   ✓
trade_date='2026-07-29': 返回 0 条, code=0      ✗
```

## 根因

`server/src/services/data_init_etf.py` sync_etf_daily 方法：
- 第 227 行已定义归一化变量 `target_date_str_yyyymmdd = trade_date.replace("-", "")`
- 但第 238 行 `tushare.get_fund_share(trade_date)` 误用原始 trade_date（可能带横杠），未用归一化值
- backfill_etf_history 传入 date.isoformat() 生成的 `2026-07-29`（带横杠），触发此 bug
- 当日采集（UC-012）若 trade_date 参数也是带横杠格式则同样受影响

## 修复

第 238 行改为 `tushare.get_fund_share(target_date_str_yyyymmdd)`（用归一化后的无横杠日期）。修复后实测日志确认：
```
拉取到 1608 条 ETF 当日份额 (trade_date=2026-07-29)   ✓ 修复生效
```

## 附加材料

- 后端日志：`/tmp/etf-uat-backend.log`
- 修复文件：`server/src/services/data_init_etf.py:238`
- 回填任务 ID：task_4ebd601f5d32（修复后重新触发，正在逐只取净值，复验中）

## 影响评估

此 bug 导致所有历史回填和任意带横杠格式的日期采集都无法获取真实份额数据。mock 测试未暴露是因为测试数据源被 patch，且测试用的固定日期巧合未触发格式问题。是 UAT 真实数据验证才暴露的关键缺陷。
