## 维度 9：代码审查

### 抽查文件

1. **`src/services/etf_monitor_service.py`**
   - `get_index_rankings`：JOIN etf_daily+etf_basic，按 index_name+category 分组，COUNT/SUM 聚合后 ÷10000 转亿份。**关键正确点**：用子查询先聚合再外层 SELECT + ORDER BY + 分页，避免外层 ORDER BY 引用聚合列时报 "missing FROM-clause entry"——结构正确，total 用 `select(func.count()).select_from(agg_subq)` 准确统计分组后指数数。sort_by 白名单 + 非法回退 netInflow 正确。
   - `get_trend`（P-08 修正）：index 类型先 JOIN/筛 index_name 得该指数 ts_code 集合（`_get_index_ts_codes`），再取该集合在 trade_date<=end_date 的最近 N 个 distinct 交易日（`group_by(trade_date).order_by(desc).limit(N)`），最后在 N 日内按 ts_code 集合聚合 SUM。**关键正确点**：交易日取自该指数 ts_code 集合（并集），非全表交易日，避免 series 长度偏差——精确符合 P-08 规格。完全无数据多处返回 hasData=false + 空 series（架构 §6.5）。
   - 单位换算：share/share_change 万份 ÷10000 亿份（`_SHARE_FACTOR=10000`），net_inflow 已亿元直接 SUM——与架构 §7.6 一致。
   - `get_index_detail`：JOIN + 筛 index_name + 默认取最新日期 + 按 netInflow 降序，份额 ÷10000 亿份——正确。
   - `get_latest_date`：JOIN etf_basic 按 category 取 MAX(trade_date)——正确（latest-date 用例通过）。
2. **`src/api/v1/etf_monitor.py`**
   - 4 GET 路由签名与契约四件套一致（query snake_case、sort_by/metric 值 camelCase、page/page_size ge/le 校验、days ge=1 le=365）。
   - `_dict_to_camel`/`_serialize_value` 与 `sector_fund_flow.py:42-67` **逐字一致**（复制方案，Task #6 决定）。
   - 每个 GET try/except + logger.exception + raise，异常流向全局处理器（AC-10 支撑）。
3. **`src/api/admin/init_etf_daily.py`**
   - 范式仿 `init_sector_fund_flow.py`：并发保护查 pending/running SYNC_ETF_DAILY（`status.in_(["pending","running"])`），存在则 `ApiResponse(success=False,...)` 拒绝；否则延迟导入 TaskManager + create_task(SYNC_ETF_DAILY) + commit + 返回 taskId。
   - require_admin 鉴权（内部 Depends(get_current_user)），并发保护逻辑正确，复用 plan-01 已验证 handler。
