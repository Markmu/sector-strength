### 建议项（非阻塞）

#### 建议项 1：`FundCrowdAnalysisPage.tsx:53` setState-in-effect lint error

- **现象**：`npm run lint` 报 `react-hooks/set-state-in-effect`（React 19 新规则）—— "Calling setState synchronously within an effect can trigger cascading renders"，定位 `useEffect` 内 `setScope/setPage/setSearch`（sessionStorage 返回状态恢复逻辑）
- **实质评估**：规则**误报**。该 effect 依赖数组为 `[]`（仅 mount 执行一次），读取 sessionStorage 后 `removeItem`，不依赖任何 state，不会因 state 变化反复触发，**不构成真实的 cascading render**。这是 React 19 规则对"从外部源初始化恢复状态"模式的过严告警。功能正确性已由 green E2E 7/7 证明。
- **修复建议**（任选其一，非本 review 强制）：
  1. 用 `useEffect` 的 `// eslint-disable-next-line react-hooks/set-state-in-effect` 局部禁用 + 注释说明"mount-once 初始化恢复"
  2. 改用 React 19 推荐的 `useSyncExternalStore` 订阅 sessionStorage（改造量大，性价比低）
  3. 将初始状态读取移到 `useState` 初始化器（lazy initializer），但 SSR 下 `window` 不可用需额外守卫
- **为何不阻塞**：(a) 规则为误报，无运行时风险；(b) 仓库基线 lint 从未达 exit 0（179 errors 历史问题），`npm run lint` 在本项目事实上非 exit-0 门；(c) plan-01 review 先例把同类非功能性告警作建议项处理。**建议后续 plan 或运维阶段统一处理仓库 lint 基线时一并修复。**

#### 建议项 2：`FundCrowdAnalysisPage.tsx:112` 无效 eslint-disable

- **现象**：`// eslint-disable-next-line no-console` 下方的 `console.warn` 实际未触发 `no-console` 规则（仓库未启用该规则或已豁免），lint 报"Unused eslint-disable directive"
- **修复**：删除该 eslint-disable 注释即可
- **非阻塞**：纯注释清理

#### 建议项 3：`CrowdIndustryDistribution` 未联动排行榜筛选

- **现象**：`onIndustryClick` prop 已声明但 `FundCrowdAnalysisPage` 未传入回调（行业标签点击无效果）
- **评估**：**符合 plan-02 范围**。plan-02 §3 #4 明示"08 不联动排行榜筛选（首版范围外，行业点击仅作可视化交互入口预留）"。联动筛选是 PRD §3.3 后续迭代项。
