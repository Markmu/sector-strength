# plan-03: 前端下钻反查复用04

## 1. 功能概要

- **目标**: 实现扎堆度排行榜的「下钻反查」闭环（AC-05）—— 用户点击排行榜某行的「反查」按钮 → 记录当前口径/页码/搜索词/**滚动位置**到 sessionStorage → 跳转 04 反查页 `/dashboard/funds/reverse-lookup?symbol={stockSymbol}&from=fund-crowd` → 04 反查页识别 `from=fund-crowd` query 参数 → 顶部条件渲染双轨口径差异提示文案（PRD §3.3 / 架构 §7.6）+ 「返回扎堆分析」入口 → 用户点击返回 → 从 sessionStorage 恢复原口径/页码/搜索词/**滚动位置**回到扎堆分析页。**完全复用 04 反查页核心逻辑**（`ReverseLookupContent` + `useReverseLookup` + `ReverseLookupTable`），仅新增 `from` query 参数的条件渲染分支 + 返回入口；**完全复用 04 `/api/v1/funds/reverse-lookup` 端点**（沿用其 stk_mkv_ratio ≥1% 展示口径，架构 ADR-4），后端零改动。
- **完成后可观察结果**: 用户在扎堆分析页（plan-02）排行榜某行点击「反查」按钮 → 浏览器路由跳转到 `/dashboard/funds/reverse-lookup?symbol=600519&from=fund-crowd`，04 反查页加载并展示最新报告期持有 600519 的基金列表（按占净值比降序，沿用 04 ≥1% 过滤）。**页面顶部新增**（仅 `from=fund-crowd` 时渲染）：固定提示文案「扎堆统计计入全部重仓记录，本表按占净值比 ≥1% 展示，个别大基金的边界持仓可能未在下钻列表中显示」+ 「← 返回扎堆分析」入口（替代或并存于原有「返回基金分析」入口）。用户点击「返回扎堆分析」→ 路由回到 `/dashboard/fund-crowd-analysis`，扎堆分析页从 sessionStorage 读取并恢复：原口径选择（仅主动/全部）、原页码、原搜索词、**原滚动位置**（scroll 恢复是 arch-check 标注的非阻塞改进项，纳入交付）。从 04 原生入口（基金分析页 → 反查）进入时，`from` 参数不存在，顶部不渲染差异提示与「返回扎堆分析」入口，04 原生体验完全不受影响。

## 3. 实现规格

### 前端部分

#### 1. `FundCrowdAnalysisPage.handleReverseLookup` 实现（路由跳转 + sessionStorage 写入）

**位置**：`web/src/components/fund-crowd-analysis/FundCrowdAnalysisPage.tsx`（plan-02 已预留 `handleReverseLookup` 占位 + `RETURN_STATE_STORAGE_KEY` 常量）。

**复用声明**：
- `useRouter` from `next/navigation`：与 04 反查页 `reverse-lookup/page.tsx:9` 一致（`import { useRouter, useSearchParams } from 'next/navigation'`）
- sessionStorage key：`RETURN_STATE_STORAGE_KEY = 'fund-crowd-return-state'`（plan-02 已定义，本 plan 复用同一 key 读写）
- scroll 恢复（arch-check 非阻塞改进项）：`window.scrollX` / `window.scrollY` 读取 + `window.scrollTo(x, y)` 恢复

**实现要点**（替换 plan-02 的占位 `handleReverseLookup`）：

```tsx
import { useRouter } from 'next/navigation'

// 在 FundCrowdAnalysisPage 组件内：
const router = useRouter()

const handleReverseLookup = (stockSymbol: string) => {
  if (typeof window === 'undefined') return
  // 记录当前状态 + scroll 位置（AC-05：返回后口径与位置保持一致）
  const returnState = {
    scope,
    page,
    search,           // 注意：记录原始 search（非 debounced），返回后重新触发 debounce
    scrollX: window.scrollX,
    scrollY: window.scrollY,
  }
  window.sessionStorage.setItem(RETURN_STATE_STORAGE_KEY, JSON.stringify(returnState))
  // 跳转 04 反查页，带 from=fund-crowd 标识（架构 §6.3 步骤 3）
  router.push(
    `/dashboard/funds/reverse-lookup?symbol=${encodeURIComponent(stockSymbol)}&from=fund-crowd`
  )
}
```

**关键规则**：
- `from=fund-crowd` 是**前端路由层标识**，不传给 04 API（04 `fundsApi.reverseLookup` 不接收 `from` 参数，仅 `symbol/page/pageSize/fundType/market/fundSearch`，见 `api.ts:415-421`）；04 反查页 `ReverseLookupContent` 用 `useSearchParams().get('from')` 读取
- sessionStorage 用 `sessionStorage`（非 `localStorage`）—— 跨标签页隔离，关闭标签页自动清理，避免长期残留；与架构 §6.3「sessionStorage 承载」一致
- `search` 记录原始值（非 debounced），返回后组件 mount 时 `setSearch(state.search)` + `setDebouncedSearch(state.search)` 同步设置，避免 debounce 延迟导致短暂闪烁（plan-02 的 useEffect 已处理）

#### 2. `FundCrowdAnalysisPage` 返回状态恢复增强（追加 scroll 恢复）

**位置**：`web/src/components/fund-crowd-analysis/FundCrowdAnalysisPage.tsx` 的 `useEffect`（plan-02 已预留读取入口）。

**复用声明**：plan-02 已实现基础恢复（scope/page/search），本 plan 追加 scroll 恢复（arch-check 标注的非阻塞改进项）。

**实现要点**（增强 plan-02 的 useEffect）：

```tsx
useEffect(() => {
  if (typeof window === 'undefined') return
  const saved = window.sessionStorage.getItem(RETURN_STATE_STORAGE_KEY)
  if (!saved) return
  try {
    const state = JSON.parse(saved) as {
      scope?: CrowdScope
      page?: number
      search?: string
      scrollX?: number
      scrollY?: number
    }
    if (state.scope) setScope(state.scope)
    if (state.page) setPage(state.page)
    if (state.search) {
      setSearch(state.search)
      setDebouncedSearch(state.search)  // 同步设置，避免 debounce 闪烁
    }
    // scroll 恢复（arch-check 非阻塞改进项）：等待数据加载 + DOM 渲染后再滚动
    // 用 requestAnimationFrame + setTimeout 双重保障（SWR 异步加载，直接 scrollTo 可能时机过早）
    if (state.scrollX !== undefined || state.scrollY !== undefined) {
      const scrollToRestore = () => {
        window.scrollTo(state.scrollX ?? 0, state.scrollY ?? 0)
      }
      // 数据加载完成后的下一帧滚动（rankings 加载后 DOM 高度恢复）
      requestAnimationFrame(() => {
        setTimeout(scrollToRestore, 0)
      })
    }
    window.sessionStorage.removeItem(RETURN_STATE_STORAGE_KEY)
  } catch {
    window.sessionStorage.removeItem(RETURN_STATE_STORAGE_KEY)
  }
}, [])
```

**关键规则**：
- scroll 恢复时机：SWR 数据异步加载，直接 `scrollTo` 可能在 DOM 高度未恢复时执行（滚动无效）。用 `requestAnimationFrame` + `setTimeout(0)` 等待下一帧；若仍有 race condition，implementer 可改用 `useEffect` 监听 `rankings` 变化后滚动（如 `useEffect(() => { if (rankings && pendingScroll) scrollTo(...) }, [rankings])`）
- sessionStorage 读取后立即清除（一次性消费）：避免用户在扎堆页刷新后误恢复旧状态
- 容错：JSON 解析失败时清除 sessionStorage，不抛错

```tsx
// line 77-86 的 syncUrl 修改：保留 from 参数（若存在）
const syncUrl = useCallback((newSymbol: string, newFundSearch: string, newFundType: string[], newMarket: string[], newPage: number) => {
  const params = new URLSearchParams()
  if (newSymbol) params.set('symbol', newSymbol)
  if (newFundSearch) params.set('fund_search', newFundSearch)
  if (newFundType.length > 0) params.set('fund_type', newFundType.join(','))
  if (newMarket.length > 0) params.set('market', newMarket.join(','))
  if (newPage > 1) params.set('page', String(newPage))
  // 保留 from 参数（plan-03）：避免筛选/翻页时 router.replace 丢失 from=fund-crowd 标识
  if (fromFundCrowd) params.set('from', 'fund-crowd')
  const qs = params.toString()
  router.replace(`/dashboard/funds/reverse-lookup${qs ? `?${qs}` : ''}`, { scroll: false })
}, [router, fromFundCrowd])
```

**注意**：`syncUrl` 的 `useCallback` 依赖数组需追加 `fromFundCrowd`（否则闭包捕获旧值）。这是 plan-03 对 04 反查页的**唯一逻辑修改**（除条件渲染外），影响范围可控（仅 URL 同步）。
