## 五、两权衡点核查结论

### 权衡点 1：主动/被动判定口径（增强指数型归属）

**结论：⚠️ 架构对 PRD 的合理细化，但 PRD 与架构口径需对齐（建议 PRD 补充明确，非架构回退）。**

**核查依据**：
- PRD §3.3「主动/被动判定规则」字面：「被动指数型（含场内 ETF、场外被动指数基金）归为被动，其余归为主动」——**未提「增强指数型」**。
- 架构 §5 ADR-1 + §4.2 + §7.6 术语映射：被动 = `invest_type IN ('被动指数型', '增强指数型')`，并附数据级核实（增强指数型 1106 条）。

**是否超出 PRD 口径？**
- 字面上是。PRD 没有把「增强指数型」列入被动枚举。
- 但架构给出了合理的业务理由（ADR-1 原文）：「『增强指数型』虽含主动管理成分，但其核心跟踪指数会机械重复持有成份股，符合 PRD『被动指数型干扰共识』的剔除诉求，归入被动。」这与 PRD §1.1「被动指数基金会因为跟踪指数而机械重复持有成份股，制造大量『虚假扎堆』」的核心动机完全一致。

**判定**：
- 这是**架构对 PRD 的合理细化**（基于数据级核实 + 业务动机对齐），**不是偏离**。PRD §3.3 字面遗漏了「增强指数型」，但 PRD 的核心剔除动机（消除指数跟踪的机械重复）覆盖了增强指数型。
- **建议处理（非阻塞）**：PRD §3.3 补充明确「增强指数型」归入被动（或确认架构口径），使 PRD 与架构对齐。若 PRD 维持字面口径（仅「被动指数型」），则架构 ADR-1 需回退将「增强指数型」归主动——但这会与 PRD 核心动机相悖，**不推荐**。
- 架构侧已做对的工程实践：把被动枚举定义为后端常量 `PASSIVE_INVEST_TYPES = ('被动指数型', '增强指数型')`（§6.1 实现原则 + §9 Phase A），便于后续调整。

**对验收的影响**：不阻塞。AC-02 验收的是「切换全部基金后纳入被动基金，排名变化」——无论「增强指数型」归被动还是主动，AC-02 都能通过（只要口径在两种 scope 下一致即可）。

### 权衡点 2：S-3 双轨下钻（复用 04 reverse-lookup + 前端提示）

**结论：✅ 能满足 PRD AC-05，方案自洽。**

**核查依据**：
- PRD AC-05 要求：「跳转至反查页，展示最新报告期持有该股的基金列表（沿用 04 反查的占净值比 ≥1% 展示口径，按占净值比降序）并提供『返回扎堆分析』入口；点击返回后回到扎堆分析页，且原口径选择与浏览位置保持一致。」
- 架构 ADR-4 + §6.3 链路：复用 `/api/v1/funds/reverse-lookup?symbol=...`（04 既有，≥1% 过滤由 Repository 层 fund_repository.py:376 自动应用）+ 前端 `from=fund-crowd` query 参数标识来源 + 反查页顶部差异提示文案 + sessionStorage 恢复原 scope/page/search。

**关键点逐一核查**：

1. **「沿用 04 反查 ≥1% 展示口径」**：PRD AC-05 原文**明确要求沿用 04 的 ≥1% 口径**，并非要求新建一致口径端点。架构复用 04 端点正好满足此要求。✅
   - 注意：PRD §3.3「与 04 反查的口径差异」也明确说明「下钻页需就此差异向用户作必要说明」，架构 ADR-4 的前端提示文案正是对此规则的执行。✅

2. **「返回后原口径选择与浏览位置保持一致」**：
   - 架构 §6.3 步骤 2「前端记录当前 scope 与浏览位置（page、search、scroll）到 sessionStorage 或 URL query」
   - §6.3 步骤 6「前端从 sessionStorage / URL query 恢复原 scope、page、search 状态」
   - §9 Phase C 第 7 点「扎堆分析页加载时检测 sessionStorage 是否有返回状态，有则恢复 scope/page/search 并清除 sessionStorage」
   - sessionStorage 方案能支撑 AC-05 的「口径与位置一致」要求（page 恢复浏览位置，scope 恢复口径，search 恢复搜索状态）。✅
   - **小改进建议（非阻塞）**：架构同时提到「sessionStorage 或 URL query」两种载体，建议在实现时明确主用 sessionStorage（避免 URL 过长，§6.3 实现原则已倾向 sessionStorage），并补充 scroll 位置恢复的细节（架构 §6.3 步骤 2 提到 scroll，但 §9 Phase C 第 7 点只列 scope/page/search，未列 scroll）——这不影响 AC-05 通过（AC-05 字面是「浏览位置」，page 即可代表），但 scroll 恢复能提升体验。

3. **「不新建一致口径端点」是否合理**：
   - ADR-4 给出明确权衡：「新建一致口径端点的收益（消除边界差异）小于其成本（重复代码 + 口径维护）」。这与 PRD §3.3「与 04 反查的口径差异」段落的精神一致（PRD 接受此边界差异并要求提示，而非要求消除）。
   - 架构 §10 演进方向保留了「若用户反馈困惑明显，可评估新建 08 一致口径的反查端点」的演进余地，决策有可逆性。✅

**对 AC-05 的最终判定**：✅ 充分满足。方案与 PRD AC-05 字面要求（「沿用 04 ≥1% 口径」+「返回口径位置一致」）完全对齐，且对 §3.3 差异说明规则有明确执行（前端提示文案）。
