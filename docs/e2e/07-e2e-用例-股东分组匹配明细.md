### 需要新增的 mock helpers（`web/tests/e2e/helpers/mock-shareholder-api.ts`）

- `createSocialGroup()` — 测试用「社保」分组（无参工厂，跟随 `createQFiiGroup()` 风格）
- `createSocialGroupWithEmptyAndZero()` — 含空关键词 + 0 匹配关键词的「社保」变体（场景 5 专用）
- `mockShareholderGroupPreviewBreakdown(page, items)` — mock `GET /api/v1/admin/shareholder-groups/preview-breakdown`
- `mockShareholderGroupPreviewBreakdownError(page, status=500)` — preview-breakdown 失败响应
- `mockShareholderGroupPreviewBreakdownSequence(page, itemsList)` — 按调用次数返回不同结果（场景 3 用，参照 `mockShareholderGroupsList` 的 `callIndex` 模式）
- `mockShareholderGroupKeywordMatches(page, data)` — mock `GET /api/v1/admin/shareholder-groups/keyword-matches`
- `mockShareholderGroupKeywordMatchesError(page, status=500)` — keyword-matches 失败响应

### 命名约束（重要）

- helper 命名跟随现有 `mockShareholderGroup*` 系列风格，**不**使用 `mockXxxSuccess`/`mockXxxError` 风格（与现有系列冲突，会让 implementer 困惑是否要重命名现有 helper）
- 错误响应变体追加 `Error` 后缀（参照现有 `mockShareholderGroupsListError` 风格）
- 工厂用 `createXxxGroup()` 无参风格，**不**使用 `createTestGroup(partial)` 风格（与 `createQFiiGroup` / `createTestShareholderGroups` 不一致）

### LIFO 注册顺序约束

`mockShareholderGroupPreview`（前缀匹配 `/api/v1/admin/shareholder-groups/preview`，line 298）会同时捕获 `/preview-breakdown` 路径。Playwright route 是 LIFO，所以 spec 中必须：

1. **先**注册前缀匹配的 `mockShareholderGroupPreview`
2. **后**注册精确匹配的 `mockShareholderGroupPreviewBreakdown`

这样 LIFO 让精确匹配在 `/preview-breakdown` 请求上优先命中；前缀匹配 fallback 处理 `/preview`。反之若顺序颠倒，前缀匹配会先捕获 `/preview-breakdown`，新 helper 永远不被调用，场景 1/2/3 会失败。
