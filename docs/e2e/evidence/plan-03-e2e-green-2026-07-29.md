**通过（16/16 green）。**

plan-03「查询 API」6 个 Task（EtfMonitorService 4 方法 / 查询路由 4 GET / v1 注册 / admin 当日采集端点 / admin 注册 / 可选 helper 采用复制方案）已在 implement 阶段全部实现，本测试（`server/tests/test_etf_monitor_api.py`）16 个用例**全部通过**：3 个构建校验（service 4 方法 + v1 路由注册 + admin 路由注册）+ 13 个 HTTP 用例（6 index-rankings + 1 index-detail + 3 trend + 1 latest-date + 2 admin）均按断言精确成立。

### 相对 red 阶段：implement 阶段已让 red 转 green（含 1 处测试 bug 修复，属路由路径层级澄清）

plan-03 的 red 测试设计**与时钟完全解耦**——`get_index_rankings`/`get_trend`/`get_latest_date` 均从入参取 `trade_date`/`end_date`（service 方法不从系统墙钟取日），测试用固定日期 `TRADE_DATE = date(2026, 7, 28)`、`PREV_DATE = date(2026, 7, 21)`，与系统墙钟无关。任意系统时钟下结论一致，无需为时钟耦合修改测试。

implement 阶段对测试做了 **1 处 bug 修复**，属**路由路径层级规格澄清**，非放宽断言：
- **背景**：red 阶段构建校验用例 `test_etf_monitor_router_registered` / `test_admin_init_etf_daily_router_registered` 最初期望从 `api/v1/__init__.py` 的 v1 子 router 与 `api/admin/__init__.py` 的 admin 子 router 的 `.routes` 里直接读到完整 `/api/v1/etf-monitor/index-rankings`、`/api/v1/admin/init/etf-daily` 路径。
- **澄清**：v1/admin 子 router 各自只含自己的 prefix 片段（`/v1/*`、`/init/*`），完整的 `/api/v1/*` 路径是在 `router.py` 经 `app.include_router(prefix='/api')` 多级组装后才拼出的，子 router 的 `.routes` 里取不到完整路径。
- **修复**：将构建校验改为检查**解析后的底层 FastAPI app routes**（`_fastapi_app.routes`，与 HTTP 用例所打的同一解析后 app 一致），而非检查子 router 的局部 `.routes`。这正是 HTTP 用例能正确命中 `/api/v1/etf-monitor/index-rankings` 的同一路径来源。
- **性质判定**：此修改是对"完整 API 路径在哪个层级出现"的实现层事实澄清（路径组装发生在 app 级而非子 router 级），**未放宽任何业务断言**——断言内容（完整路径存在）与 red 阶段完全一致，只是换到能真正读到完整路径的位置校验。HTTP 用例（13 个）未做任何修改。

这与 plan-01 green 阶段（需修正 collector 时钟耦合）不同：plan-01 当日采集用 `datetime.now(BJ_TZ)` 取日导致跨午夜失败；plan-03 查询全部参数化取日，无此风险。

### 未放宽的核心业务断言（全部保持精确值，逐条通过）

- **响应包裹与命名**：`{success: true, data: {...}}`；data 内字段 camelCase（hasData/tradeDate/indexName/totalShare/totalShareChange/totalNetInflow/etfCount/tsCode/unitNav/series 等），经 `_dict_to_camel`。
- **归集正确性（核心）**：
  - 沪深300 totalShare=140.0、totalShareChange=4.0、totalNetInflow=19.6、etfCount=2（= 510300 + 510310 之和）。
  - 中证1000 80.0/3.0/7.5/1。
  - industry 维度半导体单条 totalNetInflow=1.6、etfCount=1。
- **单位换算**：份额输出亿份（÷10000）；net_inflow 亿元；trend metric=share 时 unit='亿份'、metric=netInflow 时 unit='亿元'。
- **明细**：按 netInflow 降序（510300 20.0 在 510310 -0.4 前）；份额亿份（510300 share=120.0、shareChange=5.0）。
- **趋势**：升序序列；index share 归集=各 ETF 之和（136.0→140.0）；etf netInflow 单只曲线（15.8→20.0）；完全无数据（中证500）hasData=false + 空 series。
- **排序/分页/维度**：netInflow 降序首项=沪深300；shareChange 降序首项=沪深300；page_size=1 时 total=2（中证500 无 daily 不入聚合）、items 长度=1；industry 维度只返回半导体。
- **无数据日期**：trade_date=2020-01-01 时 hasData=false + items=[]。
- **admin**：POST 返回非空 task_id；并发保护（预置 pending SYNC_ETF_DAILY）success=false。
- **构建前置**：EtfMonitorService 4 方法（get_index_rankings/get_index_detail/get_trend/get_latest_date）、`/api/v1/etf-monitor/index-rankings` 路由、`/api/v1/admin/init/etf-daily` 路由——逐条精确断言。
