# plan-01 E2E Red 证据

## 结论

**预期失败，测试有效。**

- 后端 FEAT plan-01 为纯后端 Admin API + 数据层，E2E 形态为 **pytest API 集成测试**（参照 `server/tests/test_fund_admin_api.py` 先例），非 Playwright。
- 18 个测试用例中 **17 个失败**，失败原因均为「端点尚未实现 → 404 Not Found」，正是 red 阶段的预期信号。
- 1 个用例 `test_delete_nonexistent_returns_404` 通过，属于无害重叠：未实现的端点对任意 id（含 999999）都返回 404，与「删除不存在的分组返回 404」断言恰好一致。该用例不构成有效的 red 信号，但也不影响整体 red 判定（其余 17 个用例已充分覆盖）。
- 测试文件可被 pytest 正常收集（18 tests collected in 1.20s），无 ImportError、无语法错误——失败完全来自端点缺失，符合 red 关键原则。

- [x] 权限/认证用例同样以 404 失败（端点不存在时，认证依赖链未触发），实现端点后应自然转为 401/403。

## 给 implementer 的交接提示

- 实现时路由文件 `server/src/api/admin/shareholder_groups.py` 必须声明 `prefix="/shareholder-groups"`（参照 `users.py` / `data_status.py`），并在 `server/src/api/admin/__init__.py` 中 `include_router`，最终命中 `/api/v1/admin/shareholder-groups/*`。
- GroupListItem 响应字段必须 camelCase（`isSystem` / `ruleCount` / `matchedStockCount` / `keywords`），与 plan-01 §7 交接上下文一致——测试用例 2、16 已对此做强断言。
- AC-06 重复 name 返回 400/409、AC-10 不存在 id 返回 404——实现后 `test_delete_nonexistent_returns_404` 应回归为「真正通过」（端点存在 + 资源不存在 → 404），届时整体应转为 green。
- preview 端点路径需注意路由顺序：`/preview` 是 GET 子路径，不能被 `/shareholder-groups/{id}` 吞掉（若用同一 GET 路由，需把 `/preview` 声明在 `/{id}` 之前）。
