## implement 阶段对 spec 的测试 harness 调整说明

implement 阶段在替换 plan-04 占位为 `<EtfMonitorPage />` 后，对 spec 中 **TC-4.3 / TC-4.4 / TC-4.5** 三条 plan-04 范围用例做了 harness 调整。这些调整属于**规格演进（断言对象因实现落地而变化），而非放宽 AC 断言**。逐条说明：

| 用例 | red 阶段断言对象 | green 阶段断言对象 | 调整性质 | 是否放宽 AC |
| --- | --- | --- | --- | --- |
| TC-4.3 点击导航跳转 /dashboard/etf-monitor | 只装 sector-fund-flow 全量 mock，断言 URL 跳转 | **额外装 `installEtfMonitorMocks`** 后断言 URL 跳转（断言不变） | page.tsx 接入业务组件后进入即发 etfMonitorApi 请求；mock token 会被真实后端 401 → 触发 `handleUnauthorizedRedirect` 跳 /login，使 `toHaveURL` 失败。装 ETF mock 让目标页稳定，**断言仍是「点击导航 → 到达 /dashboard/etf-monitor」** | 否（断言未变，仅补 mock 稳页） |
| TC-4.4 页面空载渲染占位内容 | 断言占位文本「ETF 监控（建设中）」 | 装 ETF mock，断言 **业务内容可见（`etf-index-ranking-table` testid）** | plan-05 用 `<EtfMonitorPage />` 替换了占位空壳，**占位文本已合法移除**（plan-05 §3 Task #5 明确「替换占位」）。断言对象从「占位文本」演进为「业务组件渲染」，是 plan-05 落地的必然结果，非降低要求 | 否（断言对象随实现演进，要求更具体） |
| TC-4.5 页面套用 DashboardLayout | 直接 goto 断言侧边栏可见 | 装 ETF mock 后断言侧边栏可见（断言不变） | 同 TC-4.3 根因：业务组件发请求触发 401 重定向。装 mock 稳页后**断言仍是「侧边栏（板块资金流 link）可见」** | 否（断言未变，仅补 mock 稳页） |

**结论**：三条调整均为「实现落地后断言对象自然演进 + 补 mock 防止 401 重定向污染」，**核心 AC 断言（排行/趋势/排序/展开/跳转/重试等）全部保持**。TC-4.4 把占位文本断言改为业务 testid 断言，反而更精确地验证了 plan-05 的交付（page.tsx 确实接入了 EtfMonitorPage）。这与 test-e2e skill 的原则一致：spec 随实现落地合理演进，不放宽可验证的业务行为断言。
