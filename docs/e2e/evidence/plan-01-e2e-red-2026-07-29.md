# plan-01 E2E Red 证据：ETF 数据层与采集（14 期）

## 结论

**预期失败，测试有效。**

- plan-01「数据层与采集」是纯后端 task handler 功能（无 UI），SYNC_ETF_DAILY 任务是 etf_daily 表数据写入的唯一执行者。按 auto-dev / test-e2e skill 规则，task handler 功能不允许 E2E 豁免，本功能的 red 验证形态为 **pytest 集成测试（执行验证）**，非 Playwright（参照 10/11 期后端 pytest red 先例 + MEMORY「后端 FEAT E2E 适配 pytest」）。
- 新增 **10 个测试用例全部失败**，失败原因均为「目标功能尚未实现」：
  - 4 个用例 → `ModuleNotFoundError: No module named 'src.models.etf'` / `src.services.data_init_etf`（EtfBasic/EtfDaily 模型、EtfDataInitService 不存在）
  - 2 个用例 → `TaskType 未定义 SYNC_ETF_DAILY` / `sync_etf_daily handler 未注册到 TaskRegistry`（任务类型与 handler 未注册）
  - 1 个用例 → `sync_etf_daily_task 未加入 __all__`
  - 1 个用例 → `DataCollector 缺方法 _update_etf_daily`（collector 编排方法不存在）
  - 2 个执行验证用例 → 因 `TaskType.SYNC_ETF_DAILY` / `src.models.etf` 不存在，无法走到"触发任务 → 查库"的断言路径

- 现有 `tests/test_task_system.py` **15 个用例全部通过**（无回归破坏），证明本期新增测试改动未破坏既有功能。

## 断言保护强度（不放宽）

每个执行验证用例严格断言（实现后这些断言必须精确成立，非宽松通过）：

- **任务流转**：`create_task` → `start_task` → handler 执行 → `complete_task(success=True)` → `status == "completed"`（不是 running/failed）。
- **表数据正确性**：
  - etf_daily 当日记录数精确 == 3（不是 >0）。
  - share / unit_nav 非空（逐条断言，不是"至少一条有值"）。
  - 首日 share_change / net_inflow 为 null（架构 §6.1 实现原则，逐条断言）。
  - share_change = 当日份额 − 前日份额（精确值断言：510300==50000.0、512100==−10000.0）。
  - net_inflow = share_change × unit_nav / 10000（精确值断言：510300==20.0000、512100==−2.5000）。
- **幂等性**：重复执行同日采集，记录数仍 == 3（on_conflict 覆盖，非新增）；510300 share 覆盖为 1200000.0（非旧值 999999.0）。
- **归类**：etf_basic 记录数 == 3；宽基 3 只 category 全 == 'broad'；index_name 非空。
- **构建前置**：模型可导入、TaskType 定义、handler 注册、__all__ 导出、collector 方法存在——逐条精确断言，不放宽为"任意 key"。
