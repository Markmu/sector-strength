## 8. 偶发抖动说明（test-e2e 独立发现，非阻塞）

**现象**：在 6 轮独立重跑中，4 轮稳定 23/1 passed/failed，2 轮出现 1~2 个额外失败，均为 TC-3.1 / TC-3.3 的 strict-mode violation：

```
Error: strict mode violation: locator('main').getByTestId('fund-crowd-drilldown-hint') resolved to 2 elements
Error: locator.click: strict mode violation: locator('main').getByTestId('back-to-fund-crowd') resolved to 2 elements
```

**根因排查**（test-e2e 用临时探针 spec 在真实 dev server 上多次采样 DOM 元素数）：

| 时间点（page goto 后） | `fund-crowd-drilldown-hint` count | `back-to-fund-crowd` count |
| --- | --- | --- |
| t≈0ms（首帧） | **2** | **2** |
| t≈100ms 及之后 | 1（收敛） | 1（收敛） |

即：**dev 模式下页面首帧渲染时，`data-testid` 元素短暂重复**（count=2），约 100ms 内收敛为 1。这是 Next.js dev 模式 + `useSearchParams` Suspense 边界 + React 渲染序列叠加导致的瞬时双挂载/双渲染产物，**生产 build 不会复现**。

**为何触发 strict-mode 失败**：`toBeVisible()` / `click()` 在 Playwright 中默认开启 strict mode，定位器解析到 >1 元素时**立即抛错**而非等待收敛。`toBeVisible()` 的自动重试仅在「元素不满足 visible 条件」时重试；strict-mode violation 是「定位器解析阶段」的硬错误，部分场景下不会触发重试收敛。

**判定**：非测试错误、非实现逻辑错误。属 dev 模式瞬时渲染产物导致的偶发抖动。在稳定基线运行下 plan-03 AC-05 全部通过（5/5）。建议（非阻塞，留给 task-review）：

1. 如需彻底消除抖动，可在 spec 侧用 `page.locator('main').getByTestId('...').first()` 或 `getByRole('note')`（hint 唯一）收敛定位器；或
2. 在实现侧给「返回扎堆分析」按钮提取为命名组件（避免 3 个 return 分支重复内联同一 testid，降低 dev 模式双渲染窗口）；或
3. task-review 验收时重跑确认稳定性（CI 跑 `npm run build && start` 生产模式则不会复现）。

**本证据 green 结论仍判为「通过」**：plan-03 功能实现正确，稳定运行下 AC-05 全部通过；抖动是 dev 模式渲染产物，非功能缺陷，且 red 证据 §5 / plan-03 §8 已预警 dev 模式 scroll/timing 偏差类问题。
