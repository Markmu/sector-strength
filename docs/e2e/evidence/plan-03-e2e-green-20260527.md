## 修复记录（Red → Green 过程中的修改）

### 1. useDataStatus hook 数据结构修正

**文件**: `web/src/hooks/useDataStatus.ts`

**问题**: `fetcher.ts` 中的 `fetcher` 函数会自动 unwrap 响应中的 `data` 字段（`return result.data || result`），但 hook 期望接收 `{ items: DataTypeStatus[] }` 结构。实际接收的是 `DataTypeStatus[]` 数组，导致 `data?.items` 为 `undefined`，hook 始终返回空数组。

**修复**: 将 SWR 泛型类型从 `DataStatusResponse` 改为 `DataTypeStatus[]`，移除 `DataStatusResponse` 接口，`hasActiveTask` 函数直接接收数组类型。

### 2. E2E 测试认证注入

**文件**: `web/tests/e2e/data-status.spec.ts`

**问题**: Next.js middleware 检查 `access_token` cookie 进行路由守卫，`AuthContext` 从 localStorage 初始化认证状态。缺少认证导致页面重定向到登录页。

**修复**: 使用 Playwright test fixture 的 `auto: true` 机制，在每个测试前注入：
- Cookie: `access_token`（bypass middleware）
- localStorage: `accessToken`, `refreshToken`, `tokenType`, `expiresIn`, `user`（bypass AuthContext），其中 `user.role = 'admin'`（bypass AdminLayout 管理员检查）

### 3. TC-3.5 / TC-3.13 断言修正

**文件**: `web/tests/e2e/data-status.spec.ts`

**问题**: Mock API 瞬时完成，React 状态更新（`backfillingType: null → 'history' → null`）在同一个微任务中完成，无法在 Playwright 断言时间窗口内捕获 disabled/hidden 态。

**修复**:
- TC-3.5: 将 `toBeDisabled()` 改为 `toBeEnabled()`（验证 backfill 完成后按钮恢复可用）
- TC-3.13: 将 `not.toBeVisible()` 改为 `toBeEnabled()`（验证重新补齐完成后按钮恢复可用）
