# plan-03 E2E Red 证据：ETF 监控查询 API（14 期）

## 结论

**预期失败，测试有效。**

- plan-03「查询 API」是纯后端 API 功能（无 UI）：4 个 GET 查询端点（指数排行 / 指数明细 / 历史趋势 / 最新日期）+ 1 个 admin 当日采集 POST 端点。按 auto-dev / test-e2e skill 规则，API 功能的 red 验证用 **pytest API 测试**（httpx async client 经 ASGITransport 打真实 FastAPI app），不用 Playwright（参照 plan-01/02 后端 pytest red 先例 + MEMORY「后端 FEAT E2E 适配 pytest」）。
- 新增 **16 个测试用例全部失败**，失败原因均为「目标功能尚未实现」：
  - 1 个用例 → `ModuleNotFoundError: No module named 'src.services.etf_monitor_service'`（EtfMonitorService 不存在）
  - 2 个用例 → 路由未注册（`/api/v1/etf-monitor/index-rankings` 与 `/api/v1/admin/init/etf-daily` 不在 v1/admin 路由表中）
  - 13 个 HTTP 用例 → 4 个 GET + 1 个 admin POST 端点全部返回 **404 Not Found**（路由未挂载，连不到 service / handler）
- 测试文件可被 pytest 正常收集（**16 tests collected in 0.02s**），无 ImportError、无语法错误、无 collection error——失败完全来自被测功能缺失，符合 red 关键原则。
- 现有 plan-01/02 ETF 测试 **21 个用例全部通过**（test_etf_daily_sync + test_etf_history_backfill，无回归破坏），证明本期新增测试改动未破坏既有功能。

## 时钟解耦（吸取 plan-01 red 测试教训）

plan-01 的 red 测试曾因硬编码"今天"导致跨午夜失败。plan-03 是查询功能（service 方法从入参取 `trade_date`/`end_date`，不从系统墙钟取日期），本测试设计彻底避免时钟耦合：

- `TRADE_DATE = date(2026, 7, 28)`（固定最新交易日）、`PREV_DATE = date(2026, 7, 21)`（趋势历史点）作为预置数据日期与断言日期，**与系统墙钟完全无关**。
- 预置 `EtfBasic`（含 `index_name`/`category`）+ `EtfDaily`（含 `share`/`share_change`/`net_inflow`）测试数据，让聚合查询有数据可测；所有 query 参数显式传固定日期。
- 任意系统时钟下结论一致。

## 测试数据策略（确定性断言）

预置数据刻意构造覆盖 §7.2 输出 Schema 与 §7.6 单位契约的确定性断言（份额存储万份、API 输出亿份）：

- **沪深300（2 只 ETF，宽基）**：510300.SH（share=1200000万、share_change=+50000万、net_inflow=+20.0亿）+ 510310.SH（200000万、-10000万、-0.4亿）
  → 指数汇总 totalShare=140.0亿份、totalShareChange=4.0亿份、totalNetInflow=19.6亿、etfCount=2（**归集=各ETF之和**）
- **中证1000（1 只，宽基）**：512100.SH（800000万、+30000万、+7.5亿）→ 汇总 80.0/3.0/7.5
- **半导体（1 只，行业）**：512480.SH → 维度切换验证
- **中证500（仅 etf_basic，无 etf_daily）**→ trend 完全无数据 hasData=false 验证
- 趋势历史点 PREV_DATE（2026-07-21）：沪深300 share 汇总=(1150000+210000)÷10000=136.0亿份；510300 net_inflow=15.8亿

净流入额已在采集时落库（ADR-3），聚合直接 SUM，故指数汇总值可精确断言（如沪深300 totalNetInflow = 20.0 + -0.4 = 19.6 亿元）。

## 鉴权策略

- 业务 GET 端点：override `get_current_user` 返回普通登录用户（role=user）+ override `get_session` 用测试 schema 会话工厂（`auth_client` fixture）。
- admin POST 端点：override `get_current_user` 返回管理员用户（role=admin）。`require_admin` 内部 `Depends(get_current_user)`，故同一 override 同时满足两者（`admin_client` fixture）。
- `_resolve_fastapi_app` 逐层解开 `main.py` 末尾的多层中间件包裹（`ResponseLoggingMiddleware(ProcessTimeMiddleware(<FastAPI>))`）取底层 FastAPI 实例，`dependency_overrides` 正确挂载。
