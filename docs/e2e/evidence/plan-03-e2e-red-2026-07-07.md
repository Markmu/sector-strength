# plan-03 E2E Red 证据：股票读取路径切换

## 1. 摘要

本证据在 plan-03 实现前记录现状 baseline、即将切换的个股读路径清单、以及预期实现后的断言。plan-01（三新模型）/ plan-02（写入路径）已完成；写入已落新三表，但所有 `entity_type='stock'` 的读取代码仍指向旧三表（`daily_market_data` / `moving_average_data` / `strength_scores`）。

**结论：预期失败，测试有效**。实现 plan-03 后，个股读路径返回新表数据，板块读路径完全不受影响。

### 2.2 关键约束（已通过代码核查确认）

- **StockStrengthScore 无 `period` 列**：`hasattr(StockStrengthScore, 'period') == False`。所有 stock 强度读路径若保留 `period=='all'` 条件，将运行时报错 `column "period" does not exist`。
- **StockStrengthScore 无 `change_rate_5d` 列**：`hasattr(StockStrengthScore, 'change_rate_5d') == False`。`StockStrengthResponse` schema 含此字段（默认 None），但 stocks.py 响应构建必须改 `change_rate_5d=None` 硬填，不能从 ORM 取。
- **StockStrengthScore 有 `percentile` 列**（ADR-3 保证，plan-01 落地）：`hasattr(StockStrengthScore, 'percentile') == True`。`ranking_service.py:91` 的 `setattr(percentile)` 能正常写入。
- **StockMovingAverageData 保留 `period` 列**（均线表 period 是真实业务字段 '5d'/'10d'）：stock 均线读路径保留 period 条件。

## 4. 预期失败场景（Red 现象）

实现 plan-03 **之前**运行个股接口测试，预期：

1. **个股接口直接读旧表 `strength_scores` 的 entity_type='stock' 数据**——但 plan-02 之后写入已落新表，旧表不再新增 stock 数据（仅有遗留）。导致：
   - 个股强度查询返回的可能是**遗留旧数据**或**None 触发 fallback**（fallback 重算后写入新表，但读回仍查旧表 → 永远读不到刚写的新数据 → 反复 fallback）
   - 即"写入新表但读不回来"的失配现象
2. **ma_data_loader 读旧表均线数据**：plan-02 后股票均线写入新表，但 loader 读旧表 → 渐近式计算读不到新均线数据
3. **ranking_service stock 循环读旧表**：旧表 stock 强度数据不再更新，排名基于过期数据

实现 plan-03 **之后**，上述失配消失，读写对齐到新表。
