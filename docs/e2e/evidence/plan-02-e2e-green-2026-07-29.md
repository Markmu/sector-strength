### 相对 red 阶段：测试零改动，实现即满足

plan-02 的 red 测试设计**与时钟完全解耦**——backfill 接受显式 `start_date`/`end_date` 参数（不从系统墙钟取日），测试用固定日期 `BACKFILL_START = date(2026, 7, 20)`、`BACKFILL_END = date(2026, 7, 24)`，mock 交易日历也只返回这 5 天，断言查的也是这些固定日期。因此 red 证据预判的"无时钟耦合"成立，**green 阶段未对测试做任何修改**——implementer 实现 4 个 Task 后，11 个用例逐条精确通过，无需修正测试设计。

这与 plan-01 green 阶段（需修正 collector 时钟耦合）不同：plan-01 当日采集用 `datetime.now(BJ_TZ)` 取日，red spec 硬编码绝对日期导致跨午夜失败；plan-02 的回填范围是外部入参，天然无此风险。

### 未放宽的核心业务断言（全部保持精确值，逐条通过）

- **任务流转**：`create_task` → `start_task` → handler → `complete_task(success=True)` → `status == "completed"`。
- **回填范围 5 个交易日**每个都有 etf_daily 记录，每交易日记录数精确 == 3（3 只宽基 ETF）。
- **share / unit_nav 非空**（逐条断言首尾两日）。
- **首日（2026-07-20）share_change / net_inflow 为 null**（ADR-3 预期，非断裂，逐条断言）。
- **第二日 share_change = 当日 − 前日**（= 固定步长）：510300 == `Decimal("50000.0")`、512100 == `Decimal("10000.0")`。
- **net_inflow = share_change × unit_nav / 10000**：510300 == `Decimal("20.0000")`（50000×4.0/10000）、512100 == `Decimal("2.5000")`（10000×2.5/10000）。
- **全范围逐日 share_change = 当日 − 前日**（曲线连续无断裂，覆盖 ADR-5 同口径复用，5 个交易日 4 个间隔逐只断言）。
- **task.total == 5、task.progress == 5**（逐日推进）；有 AsyncTaskLog 记录（可观测性）。
- **service 直调返回** `{total_days: 5, processed_days: 5, failed_days: 0}`。
- **admin init_etf_history_router 暴露 POST /init/etf-history 端点**。
- **构建前置**：`EtfDataInitService.backfill_etf_history`、`TaskType.BACKFILL_ETF_HISTORY`（value='backfill_etf_history'）、handler 注册且 callable、`backfill_etf_history_task` 在 `__all__`、`api/admin.init_etf_history_router`——逐条精确断言。

## 数据源 mock 策略

执行验证用例通过 `unittest.mock.patch("src.services.data_acquisition.DataSourceFactory.create")` 注入确定性 mock 客户端（`get_fund_basic_etf` / `get_fund_share` / `get_fund_nav` / `get_trading_calendar`），不依赖外部 Tushare（当前 token 全局过期，不影响 green 验证）。这与 task handler 的"数据写入唯一执行者"契约无关——backfill handler 的核心职责是按日期升序逐日复用 `sync_etf_daily` 把数据写入 etf_daily 并保证 share_change 依赖上一日，数据从哪来（mock 或真实 Tushare）不影响写入与计算逻辑的验证。

mock 数据刻意构造覆盖 §5 曲线无断裂验证的确定性断言：
- 三只宽基 ETF（510300.SH / 512100.SH / 159915.SZ），与 plan-01 测试同口径便于 cross-check。
- 每只 ETF 每日份额 = 基线 + 日序号 × 步长，保证升序逐日回填时 share_change = 固定步长（510300 步长 50000、512100 步长 10000、159915 步长 5000）。
- unit_nav 固定（510300=4.0、512100=2.5、159915=3.0），net_inflow = share_change × unit_nav / 10000 可精确断言。
- 交易日历只含回填范围 5 天，保证 TradingCalendar 筛选确定。
