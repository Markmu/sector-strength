# plan-02 E2E Red 证据：股票写入路径切换

## 1. 背景

本功能是纯后端数据存储层改造（无直接用户可观察界面），将所有 `entity_type='stock'` 的写入路径从旧三表（`daily_market_data` / `moving_average_data` / `strength_scores`）切换到新三表（`stock_daily_market_data` / `stock_moving_average_data` / `stock_strength_scores`）。

依据 README §7.2 开发状态机说明：本需求的 red/green 证据对应 **pytest 失败/通过的证据**（非 Playwright）。

## 2. Red 测试策略

### 2.1 策略说明

由于这是后端改造，red 阶段采用「现状 baseline + 即将编写的新断言清单」策略：

1. **现状 baseline**：当前既有 pytest 对 stock 写入的断言指向旧表（`DailyMarketData` / `MovingAverageData` / `StrengthScore` 含 `entity_type='stock'`），在切换前**全部通过**。
2. **预期实现后的新断言**：plan-02 实现后，预期：
   - 既有 stock 写入相关测试在切换断言为新表后应通过（断言更新属 plan-04 范围，本功能不修改测试）
   - 触发股票数据写入路径后，新表应有数据，旧表不再新增 `entity_type='stock'` 记录
   - 触发股票级联删除后，新三表对应 `stock_id` 被清理，旧表板块数据不动
   - 板块写入路径（entity_type='sector'）零回归（硬门禁）

### 2.2 验证依据

本功能的"测试有效性"由以下结构保证（非运行时失败）：
- 代码静态核查：6 个目标文件当前仍引用旧表模型 + `entity_type='stock'` + 旧约束名 `uq_daily_market_data_entity_date`
- plan-01 已建好的新表模型就绪、迁移 head 在 `dd92f496dfaf`
- 切换后用 SQLAlchemy 直查新表可验证 AC-01；用直查旧表板块数据可验证 AC-04/AC-03
