### 设计要点

- **契约对齐**：mock 数据全部 camelCase，与 plan-01 §3 #3 / 架构 §7.2 一致；外层 `{ success: true, data }` 包裹（与 `mock-shareholder-analysis-api.ts` 范式一致）
- **`matchApiPath` pathname 精确匹配**：避免 glob 歧义；非自己负责的方法调 `route.fallback()`，避免 LIFO 短路（参照 `mock-shareholder-analysis-api.ts:391-413` 注释）
- **scope/search 服务端模拟在 mock 层**：spec 无需为每个 scope/search 组合单独写 fixture，handler 内动态过滤（参照 `mockShareholderSummary` 按 industry/change_direction 决定返回的范式）

### 失败根因（统一）

7 个场景的 `error-context.md` 均包含 `heading "404"` + `heading "This page could not be found."`（Next.js 404 页面结构），根因完全一致：

1. **路由 `/dashboard/fund-crowd-analysis` 不存在**（`app/dashboard/fund-crowd-analysis/page.tsx` 未创建）
2. Next.js 渲染默认 404 页面 → 页面无 `CrowdScopeSelector` / `CrowdRankingTable` / `CrowdIndustryDistribution` / `FundCrowdAnalysisPage` 任何组件
3. 所有 `data-testid="crowd-*"` 元素均 not found → 各场景在第一个 `expect()` 处超时失败

这是 plan-02 实现规格（§2 文件清单全部 `create` / `modify` 任务）尚未落地的预期表现。spec 语法正确（`--list` 验证 7 个用例被收集），mock helper 已实现且能正确注册路由拦截，断言未放宽。

### 证据完整性

- **非测试自身错误**：spec 编译通过（TypeScript 无报错），7 个用例全部被 Playwright 收集（`--list` 输出 `Total: 7 tests in 1 file`）
- **非环境错误**：dev server 正常运行（`curl http://localhost:3100/` 返回 200）；authedPage fixture 注入正常（404 页面本身不需要鉴权，证明路由层就缺失）
- **断言强度未放宽**：
  - TC-2.5（AC-06）保留「所有 3 行环比列均含『—』」+「新进标识 count=0」双断言
  - TC-2.7（AC-08）保留「600 前缀→1 行」「茅台→1 行」「无匹配→未找到匹配股票」「清空→恢复 3 条」四阶段断言
