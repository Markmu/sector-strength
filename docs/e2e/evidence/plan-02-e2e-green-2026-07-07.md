# plan-02 E2E Green 证据：股票写入路径切换

## 1. 摘要

plan-02 已由 implementer 推进到 `review`。本证据验证所有 `entity_type='stock'` 的写入路径已切换到新三表（`stock_daily_market_data` / `stock_moving_average_data` / `stock_strength_scores`），板块路径零回归（AC-03 硬门禁通过）。

**结论：通过**

## 2. 验证范围

本功能是纯后端数据存储层改造，无前端可观察界面。green 验证对应 pytest 通过 + SQLAlchemy 直查验证（依据 README §7.2 开发状态机说明）。

验证维度：
1. **代码核查**：6 个目标文件的所有 stock 写入路径已切新表
2. **AC-01 实测**：触发股票行情写入 → 落入 `stock_daily_market_data`，旧表不新增 `entity_type='stock'`
3. **AC-04 实测**：级联删除按 `stock_id` 清理新三表
4. **AC-03 板块门禁**：板块相关 pytest 零回归
5. **共享方法 ADR-4**：`_save_strength_score` 内部分发不误伤板块分支

### 3.2 AC-01 实测（SQLAlchemy 直查）

执行一次性验证脚本（已清理测试数据）：

```
[AC-01] stock_daily_market_data BEFORE write: 0
[AC-01] stock_daily_market_data AFTER write:  1
[AC-01] inserted row: stock_id=11027, symbol=688307, open=10.00, close=10.50, volume=1000.00
[AC-01] PASS: stock market data write lands in stock_daily_market_data
[AC-01] PASS: on_conflict_do_nothing idempotency holds (constraint name correct)
```

- 触发 collector 同款 `pg_insert(StockDailyMarketData).on_conflict_do_nothing(constraint='uq_stock_daily_market_data_stock_date')` → 新表新增 1 行，字段值正确
- 二次插入（同 stock_id+date）被 `on_conflict_do_nothing` 忽略，原行 close=10.50 未被覆盖 → 约束名正确，幂等性保持
- 旧表 `daily_market_data` 中 entity_type='stock' 记录数不变（切换后不再新增；遗留的 1546 行历史数据按 ADR-2 保留不读）

### 3.3 AC-04 实测（级联删除）
