## 测试设计要点

- **red 失败原因落在「Tab/组件未实现」**：TC-8.1 首断言为 `tab-market-metrics` 可见（10s element(s) not found）；TC-8.2~8.10 首动作为点击该 Tab（30s 超时）。组件不存在即失败，避免长链路误判。
- **宿主页稳定（关键，沿用 plan-07 经验）**：数据管理页默认 Tab 为「数据状态」（DataStatusPanel），会请求 `/api/v1/admin/data/status`。用 mock token 打真实后端会被 401 拒绝触发 `handleUnauthorizedRedirect` 跳 /login。beforeEach 装 `mockDataStatusNormal`（既有约定）消除该重定向，使 10 个失败全部落在「Tab 缺失」而非环境错误（截图佐证：既有六 Tab 齐全 + 默认 Tab 卡片正常 + 无 /login）。
- **mock 数据让 AC 断言有意义**：
  - 轮询序列：runningCalls=2 次后 completed，result.successCount/skippedCount/failedCount 与 dateResults 自洽（success 四类计数 daily+suspended=expected、final=daily；failed final=0 + reason 非空）
  - 记录列表：completed/failed/cancelled 三态 + total=25>page_size=20（验证分页「下一页」可见）
  - unprocessedDates：['2026-08-10','2026-08-11'] 非空（验证独立提示块）
- **与时钟/真实后端解耦**：全部用 `page.route` mock，dev server（3100）仅需可达，后端（8000）数据无关
- **testid 命名约定**（供 plan-08 实现者参照）：见用例文档「data-testid 清单」，前缀 `market-metrics-sync-`（Tab 为 `tab-market-metrics`），日期输入沿用 IndexSyncPanel 的 `aria-label` 约定
