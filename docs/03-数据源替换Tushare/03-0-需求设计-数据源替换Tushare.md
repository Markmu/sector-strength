# 03-0 需求设计：数据源替换 Tushare

## 0. 文档说明

**产品核心目标**：基于多周期均线计算板块/个股强弱，提供热力图、排名、分析等可视化功能。

**本需求定位**：现有系统正常运行 + 将数据获取层从 AkShare 替换为 Tushare + 基础设施升级，不改变任何用户可见功能。

**相关文档**：
- Tushare 官方接口文档（stock_basic / trade_cal / daily / pro_bar / ths_index / ths_daily）
- 现有数据获取层抽象接口（BaseDataSource）

---

## 1. 需求分析与确认

### 1.1 项目背景

系统当前通过 AkShare 获取 A 股行情数据（股票列表、板块列表、日线行情、交易日历）。AkShare 基于网页爬虫实现，数据稳定性依赖目标网站结构。

存在的问题：
1. **接口频繁变动**：AkShare 版本更新常导致接口名/参数/返回格式变化，需频繁适配
2. **无认证机制**：缺少 API 密钥认证，请求频率无法被合理管理，容易被限流
3. **数据获取不稳定**：高峰期爬虫接口超时率高，影响每日定时数据更新任务的成功率
4. **缺少数据完整性校验**：返回数据无版本/校验机制，无法判断数据是否完整

本期目标：将数据获取层切换为 Tushare，用户使用流程不发生任何变化，仅底层数据来源替换。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|---------|
| AkShare 接口变动导致数据获取失败 | 每日定时任务执行失败，板块强度数据无法更新 |
| 高峰期限流导致请求超时 | 管理员需手动触发数据补齐，运维成本高 |
| 无认证导致请求不稳定 | 数据更新成功率无法保障，影响下游分析和展示 |
| 网页爬虫数据源随时可能中断 | 系统可用性受制于第三方网站改版 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 数据源 | Tushare SDK | 提供 SDK + HTTP 双模式访问、积分制权限控制、数据质量有保障 | 继续使用 AkShare（不稳定） |
| 服务地址 | 使用自定义服务地址 | 部署环境需连接指定的 Tushare 服务实例，官方默认地址可能存在网络延迟或不可达 | 使用 Tushare 官方默认地址 |
| 数据范围 | 保持与现有功能完全对等 | 纯替换不应引入功能变化 | 同时扩展数据维度 |
| 旧数据源处理 | 保留 AkShare 代码作为可切换后备 | 降低切换风险，支持环境变量切换回退 | 直接删除 AkShare 代码 |

### 1.4 产品范围

**本期范围**：
- 实现 Tushare 数据源客户端，覆盖 BaseDataSource 的 4 个抽象方法（get_stock_list / get_sector_list / get_daily_data / get_sector_daily_data）及交易日历获取（get_trading_calendar）
- 解耦 TradingCalendar 服务对 AkShareDataSource 的硬编码依赖，使其跟随数据源环境变量动态切换
- 支持通过环境变量在 Tushare 和 AkShare 之间切换
- 更新系统配置以支持 Tushare 所需的认证信息

**明确不做**：
- 前端 UI 变更
- 数据库结构变更
- 新增数据维度或指标
- 修改计算逻辑（均线、强度计算等）
- 删除 AkShare 实现（保留作为后备）
- 修改 API 路由或接口定义

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

**主旅程：数据初始化与更新（系统管理员视角）**

```
管理员触发数据初始化/更新
  → 系统使用 Tushare 获取交易日历
  → 系统使用 Tushare 获取股票列表
  → 系统使用 Tushare 获取板块列表（行业 + 概念）
  → 系统使用 Tushare 获取个股日线行情（前复权）
  → 系统使用 Tushare 获取板块日线行情
  → 数据写入数据库，后续计算和展示正常进行
```

**异常旅程**：
- Tushare 服务不可用时：系统返回数据获取失败的错误信息，管理员可切换环境变量回退到 AkShare
- Tushare 积分不足访问特定接口时：对应功能返回明确的权限不足提示
- 请求频率超限时：系统自动重试（指数退避），重试耗尽后返回错误

### 2.2 用户故事

**核心用户故事**：

US-1：作为系统管理员，我希望通过管理 API 触发数据初始化时系统使用 Tushare 获取数据，以便获得更稳定可靠的数据源。

US-2：作为系统，我希望从 Tushare 获取个股前复权日线行情数据，以便均线计算和强度计算能正常进行。

US-3：作为系统，我希望从 Tushare 获取板块日线行情数据，以便板块强度排名和热力图能正常展示。

US-4：作为系统，我希望从 Tushare 获取 A 股交易日历，以便定时任务能准确判断交易日。

**延伸用户故事**：

US-5：作为开发者，我希望通过环境变量控制使用 Tushare 还是 AkShare，以便在 Tushare 服务异常时能快速回退。

## 4. 验收标准

- AC-01：交易日历获取
  前置：系统配置了有效的 Tushare 认证信息
  动作：触发交易日历获取
  结果：返回上交所交易日列表，与上交所实际交易日一致，仅包含交易日（过滤休市日）

- AC-02：股票列表获取
  前置：系统配置了有效的 Tushare 认证信息
  动作：触发股票列表获取
  结果：返回全部上市 A 股列表，包含股票代码、名称、市场类型（SH/SZ/BJ）、行业分类

- AC-03：板块列表获取
  前置：系统配置了有效的 Tushare 认证信息
  动作：分别获取行业板块和概念板块
  结果：行业板块和概念板块列表均正常返回，每条包含板块代码、名称、类型标识

- AC-04：个股日线行情获取
  前置：系统配置了有效的 Tushare 认证信息
  动作：获取指定股票在指定日期范围内的日线数据
  结果：返回前复权日线数据，包含开盘价、最高价、最低价、收盘价、成交量、成交额、换手率；成交量单位为股，成交额单位为元

- AC-05：板块日线行情获取
  前置：系统配置了有效的 Tushare 认证信息，板块数据已写入数据库
  动作：通过板块名称获取指定日期范围内的板块日线数据
  结果：返回板块日线数据，包含开盘价、最高价、最低价、收盘价、成交量；系统自动将板块名称转换为对应的板块代码进行查询

- AC-06：数据源可切换
  前置：系统同时配置了 Tushare 和 AkShare 的相关环境变量
  动作：将数据源环境变量从 tushare 切换为 akshare 并重启服务
  结果：系统回退使用 AkShare 数据源，所有数据获取功能正常运行

- AC-07：数据获取失败处理
  前置：Tushare 服务不可用或认证信息无效
  动作：触发数据获取
  结果：系统自动重试最多 3 次（指数退避），重试耗尽后返回明确的错误信息，包含失败原因和重试次数

## 5. 决策记录

| 决策日期 | 决策结论 | 首版目标 | 核心假设 | 下一步 |
|---------|---------|---------|---------|--------|
| 2026-05-31 | 使用 Tushare SDK 替换 AkShare | 保持现有全部功能不变，仅替换数据源 | Tushare SDK 支持自定义服务地址；账户积分满足板块数据接口权限（6000积分） | 确认 SDK 版本对自定义服务地址的支持方式 |
| 2026-05-31 | TradingCalendar 解耦：将 get_trading_calendar 纳入数据源抽象层 | 切换数据源后交易日历同步切换，无需手动维护两套逻辑 | TradingCalendar 对 AkShare 的调用方式与 BaseDataSource 抽象兼容 | 架构文档中确认 get_trading_calendar 是加入 BaseDataSource 还是独立接口 |
| 2026-05-31 | 数据字段映射由 Tushare 客户端内部处理 | 上层服务（DailyQuote 模型等）无需感知数据源差异 | AkShare 与 Tushare 返回的原始字段可通过客户端内部转换映射到统一模型 | 架构文档中逐字段确认映射关系 |
| 2026-05-31 | 请求频率策略：客户端内置指数退避重试 + 请求间隔控制 | 避免 Tushare 积分制下的频率超限导致封禁 | Tushare 单账户请求频率上限可查且可通过间隔控制规避 | 架构文档中确认具体频率参数 |
