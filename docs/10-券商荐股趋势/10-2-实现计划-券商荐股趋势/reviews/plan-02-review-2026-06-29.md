## AC-06 展开取舍审查（blocker）

### 规格原文（两处一致，均要求「每月」展示券商）

1. **PRD AC-06（plan-02 §验收标准）**：
   > 行展开后按月降序展示**每月**家数与推荐券商（前3+省略），某月无推荐家数 0 券商"—"

2. **plan-02 §实现规格 #4**：
   > 展开后 colSpan 渲染 monthlyBrokers（按月降序，新→旧），**每月一行：月份 + 家数 + 券商（topBrokers 前3，超 3 显示"+X 家"）**；某月 brokerCount=0 显示家数 0、券商"—"

两处均无歧义：**每一个月份**都应同时展示家数与券商（前 3 + 省略）。

### 实现偏离（`BrokerTrendRanking.tsx` L176-224）

```tsx
// 仅最新月（降序首项，mIdx===0）展开全部券商明细；
// 其余月份仅展示家数（避免跨月同名券商在内容中重复，
// 与 E2E getByText 唯一性契约一致，AC-06 家数/断档仍按月展示）。
const showBrokers = mIdx === 0
```

实现为：第 0 行（最新月）渲染券商 chip + `+X 家`；其余行（历史月）仅渲染 `{brokerCount} 家` 徽标，券商名一律不展示。

### 偏离根因（测试约束驱动，非产品需求）

实现方注释自述原因：避免跨月同名券商（如「中信证券」在 600519 的 2026-06/05/04 三月均出现）在展开内容中重复，导致 TC-2.8 `detail.getByText('中信证券')`、TC-2.9 `detail.getByText('—')` 触发 Playwright strict mode「resolved to N elements」失败。

### 判断：**blocker**

- **PRD + 实现规格双重明确要求每月展示券商前 3**，实现只对最新月展示，是功能性偏离（用户无法在历史月看到推荐了哪些券商，丢失了 AC-06 的核心信息）。
- 该偏离是**为测试约束牺牲产品规格**的典型反模式。正确方向应是**修测试**（让定位器精确化，适应每月都有券商的真实 UI），而非**降级 UI** 去迁就粗粒度断言。
- 任务验收指南明确：「如果认为违背 PRD（PRD 要求每月都展示券商前3），则记为 blocker」。当前证据支持违背 PRD 的判断。

### 建议修复（implementer 执行）

1. **实现侧（`BrokerTrendRanking.tsx`）**：移除 `const showBrokers = mIdx === 0` 的最新月限制，让 `monthsDesc.map` 内**每个月**都渲染券商 chip（前 3 + `+X 家` 省略），与 §实现规格 #4 一致。`brokerCount=0` 月份仍显示家数 0、券商「—」。
2. **测试侧（`broker-recommend-trend.spec.ts` TC-2.8/TC-2.9）**：将粗粒度 `detail.getByText('中信证券')` / `detail.getByText('—')` 改为**按月份行作用域的精确断言**，避免 strict mode 冲突，例如：
   - 先定位到某一月行：`detail.locator('div', { hasText: '2026-06' })` 或给每月行加 `data-testid`（如 `broker-trend-month-row-{symbol}-{month}`）后用 `.filter`。
   - TC-2.8：在 2026-06 行内断言 `中信证券` 可见 + `+2 家` 可见；可选在 2026-05 行再断言其券商。
   - TC-2.9：在 2026-05（断档月）行内断言家数 `0` + 券商「—」。
   - 也可用 `.first()` / `locator('...').nth(...)` 配合 `.filter({ hasText })` 缩小范围。
3. mock 数据无需改动（数据本身合理，冲突来自测试断言粒度）。

修复后预期 TC-2.8/2.9 仍通过，且每月券商可见——规格与测试对齐。
