# 05-0 需求设计：股票十大流通股东同步

## 0. 文档说明

**产品核心目标**：同步全市场每只股票的前十大流通股东信息，为后续大户持仓分析（"主力资金在进还是在出"）提供数据底座。

**本需求定位**：
- **上期基础**：sector-strength 已有行情分析（K 线、均线、强度）和基金持仓分析两个维度。
- **本期做什么**：新增"十大流通股东"数据采集能力，在管理后台新增同步任务入口，将数据落库。本期聚焦数据基础设施，不做面向用户的前端展示。
- **阶段定位**：数据底座建设。验证数据完整性与同步可靠性后，再进入前端展示和持仓分析迭代。

**相关文档**：
- 01 需求设计：自动数据质检与每日拉取补全
- 02 需求设计：数据状态总览与一键补齐
- 03 需求设计：数据源替换 Tushare
- 04 需求设计：A 股基金持仓分析

## 第一部分 需求分析与确认

### 1.1 项目背景

sector-strength 当前覆盖了"行情走势"和"基金持仓"两个观察维度，但在"个股层面的主力持仓结构"上仍是空白。一个典型的个人投资者困惑："贵州茅台的前十大流通股东里，国家队和社保基金还在不在？"——目前站内无法回答。

与基金持仓（04 期）不同，十大流通股东数据有一个关键约束：**数据源要求逐只股票单独请求**，无法像基金持仓那样按报告期一次性拉取全量数据。全市场约 5000+ 只股票需要逐一获取，单次同步预计耗时 25-30 分钟。

**具体问题**：

1. **"个股主力"无数据底座**：站内没有任何十大流通股东数据，后续的"大户持仓分析"功能无法实现。
2. **逐股票同步模式未验证**：现有数据同步任务（基金持仓、行情数据）均按报告期批量拉取，尚未支持"遍历所有股票逐只拉取"的模式。
3. **长时间同步的可靠性未验证**：25-30 分钟的同步时长需要可靠的进度反馈和断点恢复能力。

**本期目标（一句话）**：让管理员能选择报告期，触发全市场股票的十大流通股东同步，同步过程中可实时查看进度，完成后数据可靠入库。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|---|---|
| 站内无十大流通股东数据 | 后续"大户持仓分析"功能无数据基础，无法上线 |
| 无逐股票遍历同步的能力 | 现有同步任务均按报告期批量拉取，不支持"遍历全市场逐只获取"的模式 |
| 长时间同步缺乏进度反馈 | 管理员无法判断同步进度，不知道是还在跑还是卡住了 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---|---|---|---|
| 数据源 | 沿用现有数据源（Tushare） | 与项目数据源策略一致，避免多源对齐 | 自建爬虫（合规与维护成本高） |
| 同步范围 | 按报告期同步全市场所有在市股票 | 满足"全量"需求，不遗漏 | 按单只股票同步（管理成本高） |
| 本期范围 | 仅数据同步 + 管理端触发入口，不做面向用户的展示页 | 先验证数据完整性与同步可靠性，再做展示 | 一步到位做前端展示（数据未验证就做界面风险高） |
| 股东类型 | 仅前十大**流通**股东 | 流通股东对二级市场更有参考价值，限售股对个人投资者意义有限 | 同时做前十大股东（含限售，数据冗余且参考价值低） |
| 同步触发方式 | 管理后台手动触发 | MVP 不引入定时调度复杂度 | 一开始就自动定时（MVP 过重） |

### 1.4 产品范围

**本期范围（必须交付）**：

- **数据入库**：将每只股票每个报告期的前十大流通股东信息落库，包含股东名称、持股数量、占总股本比例、占流通股比例、持股变动、股东类型。
- **数据同步任务**：在现有任务体系中新增"十大流通股东同步"任务类型，支持选择报告期、触发同步、实时查看进度。
- **管理端同步入口**：在管理后台"数据管理"页面的"数据初始化"tab 中新增"股票持仓同步"按钮（与现有的"初始化板块""初始化股票"等按钮平级），支持选择报告期、触发同步、查看同步结果。

**明确不做**：

- 面向用户的十大流通股东展示页（列表、详情）
- 大户持仓分析功能（跨期对比、新进/增持/减持/退出标记）
- 股东维度的聚合查询（如"哪些股票被社保基金持有"）
- 股东身份识别与分类标签（如"国家队""社保""私募"）
- 自动定时同步
- 前十大股东（非流通）数据

## 第二部分 用户旅程和用户故事

### 2.1 核心用户旅程

**主旅程：管理员同步十大流通股东数据**

```
[1. 管理员进入"管理 / 数据管理"页面，切换到"数据初始化"tab]
   ↓
[2. 在现有初始化按钮列表中找到"股票持仓同步"，选择报告期（如 2025-03-31）]
   ↓
[3. 点击"同步"按钮]
   ↓
[4. 按钮变为"同步中…（1,847 / 5,234）"并禁用，进度实时更新]
   ↓
[5. 同步完成，页面展示"新增 X 条 / 更新 Y 条 / 失败 Z 只股票"]
   ↓
[6. 管理员在下方任务记录中确认本次执行结果]
```

**异常旅程**：

- **部分股票失败**：同步过程中某些股票因数据源接口异常（限流、超时）获取失败，任务不中断，失败股票单独记录。同步完成后统计中体现失败数量，管理员可重新触发同一报告期同步，系统不重复处理已成功的股票。
- **同步立即失败**：若首次调用即返回认证错误或权限不足，任务立即失败，提示具体原因。

### 2.2 用户故事

**核心用户故事**：

- **US-01**：作为管理员，我希望在"数据管理 → 数据初始化"页面选择报告期并触发"股票持仓同步"，以便为后续大户持仓分析积累数据。
- **US-02**：作为管理员，我希望在同步过程中看到实时进度（已处理 X / 共 Y 只股票），以便判断同步还需多久。
- **US-03**：作为管理员，我希望同步完成后看到统计结果（新增、更新、失败数量），以便确认数据完整性。

**延伸用户故事**：

- **US-04**：作为管理员，我希望同步过程中个别股票失败不会中断整体任务，失败股票单独记录，以便后续针对性补拉。
- **US-05**：作为管理员，我希望重复触发同一报告期同步时不会产生重复数据，以便安全地重试。

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
|---|---|---|
| 未同步过 | 按钮下方显示"尚未同步过"，报告期下拉框可选 | 选择报告期并点击同步 |
| 同步中 | 按钮变为"同步中…（X / Y）"并禁用，显示进度条和实时统计 | 等待完成 |
| 同步完成（全部成功） | 展示"新增 X 条 / 更新 Y 条 / 失败 0 只股票" | 无需操作 |
| 同步完成（部分失败） | 展示统计 + 失败股票数量 | 可重新触发同步补拉 |
| 同步失败（任务级） | 弹窗提示"同步失败：xxx 原因" | 检查原因后重试 |
| 已有数据 | 按钮下方显示上次同步的报告期、时间、记录数 | 可选择新报告期同步 |

### 3.3 业务规则

- **报告期选择**：下拉框展示最近 8 个季度的报告期（如 2025-03-31、2024-12-31 …），默认选中最近一个。也可手动输入。
- **同步范围**：同步时遍历系统中已收录的所有在市股票，逐只获取其十大流通股东数据。
- **幂等性**：同一报告期重复同步时，不产生重复数据。系统会清除该报告期旧数据后写入新数据。
- **进度追踪**：同步过程中实时显示已处理股票数 / 总股票数。
- **失败处理**：单只股票获取失败不中断整体同步，失败股票单独记录（含股票代码和失败原因），最终在同步结果中汇总。
- **空数据正常化**：某些股票在指定报告期可能尚未披露或数据源未收录，返回空数据属正常现象，不计为失败。

## 第四部分 验收标准

- **AC-01：触发同步任务**
  前置：当前用户为管理员角色。
  动作：管理员进入"数据管理 → 数据初始化"tab，在"股票持仓同步"区域选择报告期"2025-03-31"，点击"同步"。
  结果：按钮变为"同步中…"并禁用，后台开始执行同步任务。

- **AC-02：数据入库**
  前置：管理员已触发同步任务。
  动作：等待任务执行完成。
  结果：系统中包含指定报告期全市场股票的十大流通股东数据，每条记录包含股票代码、公告日期、报告期、股东名称、持股数量、占总股本比例、占流通股比例、持股变动、股东类型。

- **AC-03：进度实时反馈**
  前置：同步任务正在执行中。
  动作：管理员查看同步区块。
  结果：显示"同步中…（X / Y）"和进度条，X 和 Y 随同步推进实时更新。

- **AC-04：部分失败不中断**
  前置：同步过程中某只股票的数据获取返回异常。
  动作：任务继续执行。
  结果：该股票记录到失败列表，其他股票正常同步，任务最终完成（非失败），统计中体现失败数量。

- **AC-05：同步统计展示**
  前置：同步任务已完成。
  动作：管理员查看同步区块。
  结果：展示"新增 X 条 / 更新 Y 条 / 失败 Z 只股票"统计，同步记录表中追加一条记录。

- **AC-06：幂等性**
  前置：已完成一次报告期"2025-03-31"同步。
  动作：管理员再次触发同一报告期同步。
  结果：数据不重复，统计与首次结果一致。

- **AC-07：同步失败提示**
  前置：数据源返回认证错误或权限不足。
  动作：同步任务执行。
  结果：任务状态标记为失败，提示具体原因，前端弹窗展示错误信息。
