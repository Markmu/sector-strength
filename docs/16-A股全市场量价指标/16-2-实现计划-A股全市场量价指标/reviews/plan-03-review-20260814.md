| 指标 | 公式 | 测试断言（BASE_DAILY: vol=100/200/300, amount=50/100/30, close=10.5/20.0/5.0） | 复算结果 |
| --- | --- | --- | --- |
| volume_shares | Σ(vol×100) | `Decimal((100+200+300)*100)` = 60000 | ✅ 一致 |
| amount_yuan | Σ(amount×1000) | `Decimal((50+100+30)*1000)` = 180000 | ✅ 一致 |

**关键场景复算：**

- **Decimal 精度陷阱**（`test_decimal_precision_no_float_accumulation`）：amount=1.1/2.2/3.3 千元 → `(1.1+2.2+3.3)*1000 = 6600` 精确（float 会得 6600.000000000001），断言 `amount_yuan == Decimal("6600")` ✅。证明全程 Decimal、无 binary float 累积误差。
- **全天停牌补值**（`test_full_day_suspended_supplemented_with_last_close`）：3 daily + 1 suspended(close=8.0)，volume/amount 不含停牌（0），average_price=(35.5+8.0)/4=10.875，final_stock_count=4 ✅。

- **同日覆盖恰一行**（`test_sync_date_repeat_overwrites_same_row`）：二次 sync 后 `len(rows)==1`，`volume_shares` 被覆盖为新值 ✅。

## 13. 后补丁记录 #2（2026-08-14）：init_stocks_lifecycle 逐股 savepoint 无限递归修复

### 13.1 缺陷根因

plan-05 执行验证（真实 task handler）暴露：`init_stocks_lifecycle` 的逐股 `_safe_nested_tx`
（`session.begin_nested()` savepoint）循环在真实规模（L/D/P/G 合计 ~5882 股）下触发
**无限 RecursionError**：

- 崩溃点：`sqlalchemy/sql/compiler.py::visit_rollback_to_savepoint` →
  `preparer.format_savepoint`（编译 `ROLLBACK TO SAVEPOINT sa_savepoint_N` 时无限递归）。
- 验证：`sys.setrecursionlimit(8000)` 仍崩溃（确认真无限递归，非深但有限）；traceback 1999 行。
- 定位：逐股**业务逻辑本身无错**——把 `_safe_nested_tx` 临时替换为 no-op context manager 后，
  `init_stocks_lifecycle` created+updated+skipped 合计=total=5882，**0 errors**，5.4s 完成。

- 影响：生产任务 preflight 会崩溃（blocker 级）；并导致 stocks 表此前仅落 L 状态（D/P/G 缺失）。

### 13.2 修复方式

`server/src/services/data_init.py` 的 `init_stocks_lifecycle`：

- **去掉逐股 savepoint 循环**，改为单事务内 `pg_insert(Stock)` 批量 upsert（`_LIFECYCLE_BATCH_SIZE=500` 行/批）。
- **预加载分区**：一次 `select` 查现有股票生命周期字段，精确区分 `insert`（新 symbol）/
  `update`（字段变更）/ `skipped`（未变更），保持原 created/updated/skipped 计数语义。
- 新行 `pg_insert` 含 `current_price/market_cap=None`（匹配原 ORM 新建）；变更行走
  `on_conflict_do_update(index_elements=["symbol"], set_={生命周期字段 + updated_at=func.now()})`
  （`symbol` 为 Stock 表唯一键，**非 ts_code**；匹配原按 symbol 查询的键语义）。
- **整批失败回退逐行**：批级 `try/except`，失败时 rollback 本批后逐行重试（每行独立提交），
  问题行记入 `errors`（含 ts_code 样本）；每批独立提交以隔离失败批次（Postgres 语句失败中止事务）。
- 既有语义完全不变：记录级校验（`validate_lifecycle_records`）、upsert 字段映射、四状态联合
  set-diff 清理（`_cleanup_disappeared_stocks`，港股传 `None` 跳过）、返回统计 dict。
- 旧 `init_stocks()`（历史路径）未改行为，仅在 docstring 标注同风险（若后续崩溃可参照改造）。
