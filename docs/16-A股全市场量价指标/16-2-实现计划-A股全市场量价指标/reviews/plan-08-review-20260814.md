## 4. 重点裁定 A：AdminApiClient.request `success===false` 抛错（共享代码变更）

### 4.1 变更内容

`web/src/lib/api.ts` 的 `AdminApiClient.request`（L521-524）新增：HTTP 200 但 `json.success === false` 时抛 `Error(message)`。git 确认 HEAD（committed）无此检查，本变更为 plan-08 工作树引入。

```ts
if (json && json.success === false) {
  const rejectMsg = json.message || json.error?.message || '操作被服务端拒绝'
  throw new Error(rejectMsg)
}
```

影响面：所有走 `adminApiClient`（含 `adminApi.*`）的调用方。**不影响** `apiClient`（父类 `ApiClient.request` 未改），故 `marketMetricsApi`/`indexMonitorApi`/`etfMonitorApi`/`shareholderAnalysisApi`/`sectorFundFlowApi` 等查询 API 不受影响。

### 4.2 全量消费点 grep 与行为分析

`adminApi.*` 消费点（src/）：

| 调用方 | 方法 | 响应处理模式 | success=false 行为变化 |
| --- | --- | --- | --- |
| MarketMetricsSyncPanel | initMarketMetrics | `response.data?.task_id` + try/catch | 同款（本功能） |
| IndexSyncPanel | initIndexBasic/Daily/History | `response.data?.task_id` + try/catch | 旧：抛"未返回任务 ID" → 新：抛真实 message；同一 catch 路径，仅 message 更准 |
| EtfSyncPanel | initEtfBasic/Daily/History | 同上 | 同上 |
| LimitSyncPanel | initLimit | 同上 | 同上 |
| BrokerRecommendSyncPanel | initBrokerRecommend | 同上 | 同上 |
| StockTop10SyncPanel | initStockTop10Holders | 同上 | 同上 |
| FundSyncPanel | initFundBasic/Portfolio | 同上 | 同上 |
| UserManagementPanel | listUsers/getUserStats/updateUser* | try/catch（不读 success 字段） | 读类操作 success=true 为常态；异常路径仍进 catch |
| ShareholderGroupPanel | getShareholderGroups/delete | try/catch（不读 success 字段） | 同上 |
| ShareholderGroupEditor | preview/create/update | try/catch（不读 success 字段） | 同上 |

**关键发现：没有任何 `adminApi` 调用方在调用后检查 `response.success` / `response.data.success` 字段。** 唯一一处 `.success` 检查位于 `IndexSyncPanel.tsx:444`（`indexMonitorApi.updateWatchlist`），但该方法走 `apiClient.put`（父类，未改），返回完整响应体，不受影响。

由于 `AdminApiClient.request` 本就提取 `json.data`（L527 `return { data: json.data }`），消费方从 `response.data` 也无法读到顶层 `success` 字段——历史上不存在"success=false 不抛错、自行检查 success 字段"的依赖模式。

### 4.3 既有 E2E 覆盖 success=false 分支的 spec

- **admin-etf-sync.spec.ts**「并发保护拦截展示提示」（L148-160）：mock 返回 `{success:false,data:null}` HTTP 200，断言 toast `/创建采集任务失败/`。变更前：`data.task_id` 为 undefined → 抛"未返回任务 ID" → toast"创建采集任务失败: 未返回任务 ID"；变更后：抛真实 message → toast"创建采集任务失败: <真实原因>"。**两条路径均命中同一正则断言**。本次复跑 12/12 通过。
- **admin-fund-sync.spec.ts**「同步互斥」（L280）：测的是前端按钮 disabled（mock running 任务），不涉及 success=false 响应。不受影响。
- **shareholder-groups.spec.ts**：无 success=false / reject 引用。不受影响。

### 4.4 裁定

**接受，非 blocker。** 该变更是行为改进（业务拒绝展示真实 message 而非泛化"未返回任务 ID"），不引入任何回归：所有受影响调用方原本就在 try/catch 中以 error 路径处理 success=false，变更后仍在同一 catch 路径，仅 message 更准确。唯一覆盖 success=false 的既有 E2E（admin-etf-sync）复跑通过。无需回退、无需改为组件内处理。

> 备查：若未来后端有 admin 读接口以 HTTP 200 + `success=false` 表达"空结果"（非异常），则该变更会将其转为抛错。当前所有 admin 读接口（listUsers/getShareholderGroups/preview 等）均以 `success=true` + 空数组/null 表达空态，无此风险。

## 5. 重点裁定 B：displayResult 三级回退

```ts
const recordResult = syncRecords.find((r) => r.result)?.result ?? null;
const displayResult = terminalResult ?? task?.result ?? recordResult;
```

| 层级 | 来源 | 用途 |
| --- | --- | --- |
| terminalResult | useTaskStatus onComplete/onFailed/onCancelled 回调写入 | 本地任务终态结果（最高优先） |
| task?.result | 当前轮询 task 对象的 result | 回调未触发时（如 jest 全量 mock）回退 |
| recordResult | 记录列表首条带 result 的记录 | 直接打开 Tab 查看历史（无本地任务在跑） |

**裁定：接受，非 blocker。** 回退顺序合理：

- 本地任务运行/终态时，terminalResult / task.result 优先，展示用户刚发起任务的真实结果。
- 无本地任务时取最近一条带 result 的历史记录（记录按 createdAt 倒序，`find((r) => r.result)` 取最近完成任务），符合"查看上次同步结果"语义。
- 不存在展示错误数据风险：所有 record 均为 `task_type=sync_market_metrics`（SWR key 已过滤），数据同源。

**非阻塞建议（S-1）**：当本地任务处于 running（非终态）时，`terminalResult=null` 且 `task.result=undefined`，会回退到 `recordResult`，结果区会显示"上一次完成结果"而非隐藏。进度区已独立显示运行态，故非数据错误，但可在后续迭代中于 `localRunning` 时隐藏结果区以减少视觉歧义。不阻塞本次验收。

### 8.1 契约对齐（维度 8）

- **result camelCase 直消费**：后端 `server/src/services/task_handlers.py` L1771-1775 构造 result 时键即 camelCase（`successCount/skippedCount/failedCount/dateResults/unprocessedDates`），`to_dict()` 原样透传不经 `_dict_to_camel`。前端 `MarketMetricsTaskResult`/`MarketMetricsDateResult` 类型键与之一致，无二次转换层。三方契约（plan-05 产出 / plan-04 透传 / plan-08 消费）对齐。
- **body snake_case**：`initMarketMetrics(start_date, end_date)` body `{ start_date, end_date }`，与后端 Pydantic payload 一致，与既有 `initIndexHistory`/`initLimit` 同款。
- **endpoint 拼接**：`/admin/init/market-metrics` × AdminApiClient baseURL `${API_BASE_URL}/api/v1` = `/api/v1/admin/init/market-metrics`，与后端挂载一致。
- **响应解包**：`adminApiClient.post<{ task_id: string }>` 返回 `ApiResponse.data = { task_id }`（snake_case，与 initLimit/initIndexHistory 同款），`startSync` 读 `response.data?.task_id`。一致。
- **records SWR**：key `/api/v1/admin/tasks?task_types=sync_market_metrics&page=N&page_size=20` + `fetcher`（返回 `result.data`），与 IndexSyncPanel `RECORDS_SWR_KEY` 同范式，URL 不双前缀。
