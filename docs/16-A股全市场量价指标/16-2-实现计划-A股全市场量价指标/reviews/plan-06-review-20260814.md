## 三、实现偏差特别裁定：Query 签名 `int` → `str`

- **计划签名**: `range: int = Query(30, pattern="^(30|90|250)$")`
- **实现签名**: `range: str = Query("30", pattern="^(30|90|250)$")` + 端点内 `range_days = int(range)`
- **偏差理由核实（实证）**: FastAPI 0.127.0 / Pydantic 2.12.5 下，`int + pattern` 在**请求时**抛 `TypeError: Unable to apply constraint 'pattern' to supplied value 30 for schema of type 'int'`（定义期与 OpenAPI 生成期不报错，隐蔽）。原计划签名会导致 `?range=30` 返回 500 而非正常 200，属真实缺陷。
- **线上契约影响核对**:
  | 输入 | 计划意图 | 实际行为（str 实现） | 一致？ |
  | --- | --- | --- | --- |
  | 无参 | 默认 30 | `"30"`→`int("30")=30` | ✅ |
  | `?range=30/90/250` | 取对应值 | pattern 通过→`int()` 转换 | ✅ |
  | `?range=50` | 422 拒绝 | pattern 拒绝→422 | ✅ |
  | 响应 `range` 字段 | int | 输出 `range_days`（int） | ✅ |
- **新风险核查**:
  - Query 参数 OpenAPI 类型由 integer 变 string：无影响——前端始终以 URL 字符串发请求，且只读响应 `data.range`（int）。
  - `pattern` 作用于 str 实际比 int 解析更严（拒绝 `"030"`/`"30.0"`），与"仅允许 30/90/250"的原始意图一致，无回退。
- **裁定结论**: **接受**。偏离有据（环境实证 TypeError），线上契约完全不变，无新增风险，且代码注释（market_metrics.py:106-109）已记录原因。属"环境事实驱动的等价实现"，不构成 blocker。
