### 5.3 残留 `.or()` 兜底选择器合理性

**统计**: spec 中 `.or()` 兜底选择器共 5 类（每类多处使用）：

| 类别 | 主选择器 | 兜底选择器 | 合理性 |
| --- | --- | --- | --- |
| 卡片定位（TC-4.3/4.4/4.5/4.6/4.7/4.8/4.10） | `main.locator('[data-testid="group-card-1"]')` | `main.getByText('国家队', { exact: true }).first().locator('xpath=ancestor::*[...]')` | 合理——data-testid 命中实现侧补的稳定标记，文本兜底防御 testid 命名变更 |
| 行业筛选下拉（TC-4.5） | `detail.locator('[data-testid="industry-filter"]')` | `detail.getByRole('button').filter({ hasText: /行业|全部行业/ })` | 合理——下拉选择器 testid 优先 + trigger 按钮文本兜底 |
| 变动方向筛选（TC-4.7） | `detail.locator('[data-testid="change-direction-filter"]')` | `detail.getByRole('button').filter({ hasText: /变动方向|全部方向/ })` | 合理 |
| 报告期选择器（TC-4.8） | `main.locator('[data-testid="report-period-selector"]')` | `main.getByRole('button').filter({ hasText: /2024-12-31|报告期/ })` | 合理 |
| 行业分布图（TC-4.3） | `detail.locator('[data-testid="industry-distribution-chart"]')` | `detail.getByText(/行业分布/)` | 合理（注：实现侧标题用"行业占比"，故正则未直接命中标题；但容器 testid 命中，spec 通过） |
| option 选项定位（TC-4.5/4.7/4.8） | `page.getByRole('option', { name: 'xxx' })` | `page.locator('[role="option"]').filter({ hasText: 'xxx' })` | 合理——role=option 是 SimpleSelect 提供的稳定结构标记 |

**判断依据**：
- 所有 `.or()` 都是「data-testid 主选择器（实现侧已补齐）+ 文本/容器兜底」的双选择器容错模式，符合 E2E 规则 7（稳定结构化标记优先）的精神。
- 兜底选择器非"掩盖失败"——主选择器命中即跳过兜底；只有主选择器失效（如 testid 被改名）时才尝试兜底。这是工程惯例，不是"或运算掩盖测试失败"。
- 实现侧补齐了所有 testid（group-card-{id} / holdings-detail / industry-distribution-chart / industry-bar-{industry} / industry-filter / change-direction-filter / report-period-selector），spec 主路径全部命中。

**结论 3**: **残留 `.or()` 合理**，属于规范的双选择器容错模式，非掩盖失败的脆弱写法。

### 5.4 综合判断
