### 5.5 建议项（非阻塞）

**S-1（建议）：`get_summary` 中 `industry_map` 未包含 exit 股票 symbol**

- 位置：`shareholder_analysis_service.py:514`
- 现状：`industry_map = await self._get_industry_for_stocks(list(current_holdings.keys()))`，仅解析当前期股票；随后 exit 股票行（service.py:532-543）通过 `industry_map.get(symbol, {}).get("industries", [])` 取行业，因 exit symbol 不在 map 中，恒返回 `[]`。
- 影响：当 `change_direction=exit` 与 `industry=银行` 同时传入 summary 接口时，退出股票无法通过行业筛选（退出股票的行业信息缺失）。`get_industry_distribution`（service.py:649）和 `get_holdings`（service.py:751）已正确包含 `list(current_holdings.keys()) + list(exit_holdings.keys())`，无此问题。
- 触发频率：低（summary + exit + industry 组合筛选为边界场景，前端 plan-04 实际 UI 流程中 summary 通常不带 change_direction=exit）。
- 修复建议：将 service.py:514 改为 `_get_industry_for_stocks(list(current_holdings.keys()) + list(exit_holdings.keys()))`，与 holdings/distribution 保持一致。
- 当前未列入 blocker：plan-02 §3.3 的 get_summary 规格未显式要求 exit 股票参与 industry 筛选；测试用例未覆盖该组合；前端实际流程不触发。

**S-2（建议）：`_get_report_periods` 对"传入但不在列表中的 report_period"静默回退到最新期**

- 位置：`shareholder_analysis_service.py:104`
- 现状：当 `report_period` 不在 `period_dates` 列表中（如传了未来日期或拼写错误的日期），`current_date` 被重置为 `period_dates[0]`（最新期），不报错也不告警。
- 影响：调用方误传报告期时得到的是"最新期"而非错误，可能掩盖前端 bug。
- 严重度：低（前端会从 overview 的 reportPeriods 下拉取值，不会误传）。
- 修复建议：可选——对"传入但不在列表"的情况记 warning 日志（架构 §8.5 可观测性），或保留现状作为容错。
