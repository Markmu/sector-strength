# UAT 失败证据：UC-010 编辑分组返回值陈旧

**Case ID:** UC-010
**用例标题:** 管理员编辑匹配规则
**执行日期:** 2026-06-13 22:30
**执行人:** MUCHAO
**执行状态:** Failed（响应数据不准；DB 实际更新正确）

## 失败摘要

`ShareholderGroupService.update_group` 在整体替换关键词后，**返回的 `keywords` / `rule_count` 是更新前的值**，而非更新后的新值。数据库实际已正确更新（`list_groups` 重新查询得到正确值），仅该接口的响应体陈旧。

## 复现

```python
# 创建 UAT测试组（2 关键词）
new = await g.create_group("UAT测试组", "...", ["中央汇金", "高盛"])   # rule_count=2

# 编辑：追加"摩根大通"（应变为 3 关键词）
upd = await g.update_group(new["id"], keywords=["中央汇金", "高盛", "摩根大通"])
print(upd)  # {"rule_count": 2, "keywords": ["中央汇金", "高盛"]}  ← 旧值（应为 3）

# 重新 list 验证 DB
groups = await g.list_groups()
# UAT测试组 ruleCount=3, matchedStockCount=1040  ← DB 是新的（正确）
```

实测输出：
- `update_group` 返回：`rule_count=2, keywords=["中央汇金","高盛"]`（旧）
- `list_groups` 实查：`ruleCount=3`（新，正确）

## 根因分析

代码位置：`server/src/services/shareholder_group_service.py:282-300`

```python
if keywords is not None:
    await self.repo.replace_rules(group.id, keywords)   # 删旧+加新
await self.session.commit()
group = await self.repo.get_by_id_with_rules(group_id)  # 重新查询，但返回缓存的 rules
rule_keywords = [rule.keyword for rule in group.rules]  # ← 拿到旧的 2 个
```

`replace_rules` 在同一 session 内 delete 旧 rules + add 新 rules，commit 后 `get_by_id_with_rules`（selectinload rules）受 SQLAlchemy **identity map / 关联集合缓存**影响，返回了 expire 前的 rules 关联快照，未反映新插入的规则。

## 影响

- plan-03 前端编辑分组保存后，若用 `update_group` 响应体即时刷新表单/列表，会显示旧关键词（用户看到"保存了但关键词没变"的错觉）。
- 若前端保存后重新调 `list_groups`，则显示正确（plan-03 spec TC-1.5 验证的是 list 刷新，故 Playwright green 未暴露）。
- 严重性：中等（DB 数据正确，仅响应体不准；影响编辑即时反馈）。

## 修复建议

commit 后强制让 session 过期/重新加载关联，任选其一：

```python
# 方案 A：commit 后 expire 该 group
await self.session.commit()
self.session.expunge_all()   # 或 expire group
group = await self.repo.get_by_id_with_rules(group_id)

# 方案 B：用全新查询（绕过 identity map），如直接查 rules 表
```

或调整 `replace_rules` / `get_by_id_with_rules` 确保 commit 后 selectinload 取最新。需补一个 pytest 用例：update 后断言返回的 keywords == 新传入的列表。
