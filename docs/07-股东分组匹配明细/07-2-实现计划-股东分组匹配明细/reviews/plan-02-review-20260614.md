## 4. AC-09 收紧说明（red spec 修改把关，MEMORY）

任务说明中重点要求核查的「AC-09 0 匹配置灰」收紧：

- **plan-02 §3 #6 样例代码**：`disabled={countItem?.matchedStockCount === 0 || countItem?.error}`
- **实际实现**（`ShareholderGroupPanel.tsx:704`）：`disabled={countItem?.matchedStockCount === 0`

**复核结论**：这是合理的收紧，不是放宽断言。

- **逻辑层面**：去掉 `|| countItem?.error` 后，错误状态时按钮仍可点击；点击会触发 `handleViewDetail` → `reloadDetail`，明细查询失败时由明细区独立 try/catch 显示「加载失败 重试」（AC-07 失败可重试路径）。这与 AC-07「失败可重试」语义一致，更符合用户预期。
- **断言层面**：TC-2.5（AC-09）的 spec 断言未受影响——`view-detail-2`（matchedStockCount === 0）依然 disabled，`view-detail-0`（matchedStockCount === 2）依然 enabled。错误状态的按钮 disable 行为原本就没有 spec 断言约束。
- **风险**：仅当某个关键词行进入 error 状态时按钮可点。点开后明细区也会进入 error 状态显示重试按钮，闭环正确。

### TC-2.3/2.4/2.5 补 `mockShareholderGroupPreview` 注册

任务说明要求复核此判断是否是「补 mock 让测试条件成立」vs「放宽断言」。

- **TC-2.3**（`spec.ts:455`）：注册 `mockShareholderGroupPreview(page, 2)`
- **TC-2.4**（`spec.ts:502`）：注册 `mockShareholderGroupPreview(page, 2)`
- **TC-2.5**（`spec.ts:540`）：注册 `mockShareholderGroupPreview(page, 2)`

**复核结论**：是补 mock 让测试条件成立，不是放宽断言。

- 这三个场景原本只注册了 `mockShareholderGroupPreviewBreakdown*`，但 debounce effect 内并行调用了 `previewShareholderGroupMatch`（合并预览，AC-02）+ `previewShareholderGroupMatchBreakdown`（逐关键词，AC-01）。合并预览未 mock 时返回 401，触发 `handleUnauthorizedRedirect` → 整页跳转 `/login`，导致后续断言完全无法执行。
- 补的 mock 用的是 `mockShareholderGroupPreview` 前缀匹配（捕获 `/preview`，但 `/preview-breakdown` 是后注册的精确匹配 helper 优先命中），不会改变 breakdown 的 mock 行为。
- TC-2.3/2.4/2.5 的断言条件（`keyword-count-0` 含「N 只」、按钮 disabled/enabled）均未放宽，反而确保了 debounce 的合并预览路径可被正确测试。
- green 证据 §6 已明确记录此修改为「spec bug 修复，非断言放宽」。
