# 07-0 需求设计：股东分组匹配明细

## 0. 文档说明

**产品核心目标**：基于十大流通股东数据，通过"关键词监控组"帮助管理员识别重要股东的资金动向，并在用户侧呈现持仓聚合分析。

**本需求定位**：股东监控组管理（已上线） + 编辑分组时查看每个关键词的匹配股数与明细下钻（本期） + 增量体验优化阶段。

**相关文档**：
- `docs/06-股东分析面板/` — 监控组管理 + 持仓聚合查询 + 分析面板（上一期）
- `docs/05-股票十大流通股东同步/` — 十大流通股东数据同步（数据基础）

## 第一部分：需求分析与确认

### 1.1 项目背景

**产品当前状态**：管理员可在"股东监控组管理"页面创建分组、配置若干匹配关键词，系统按"股东名称包含关键词"的规则匹配十大流通股东，聚合出每组监控的股票持仓。编辑分组时，系统已提供"匹配预览"，但该预览仅展示**所有关键词合并后的总匹配股数**。

**存在的问题**：
1. **看不出每个关键词的贡献**：编辑时只看到一个合并总数。当总数异常（偏多或偏少）时，管理员无法判断是哪个关键词导致，只能逐个删除关键词反复试错。
2. **关键词质量无法评估**：股东名称模糊匹配容易"误伤"（如关键词过短会匹配到大量无关股东），管理员在保存前看不到具体匹配到哪些股票和股东，可能保存出充满噪音的分组。
3. **无明细下钻入口**：即使发现某关键词匹配数可疑，也没有任何入口查看具体匹配清单，必须先保存，再切换到用户侧分析面板反查，链路断裂。

**本期目标**：让管理员在编辑分组时，能一眼看到每个关键词分别匹配多少只股票，并能即时下钻查看该关键词匹配的股票清单（股票代码 + 股票名称 + 股东名称），实现"保存前自检"。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|---------|
| 只能看合并总数，看不出每个关键词的贡献 | 关键词质量问题定位困难，需反复删改试错 |
| 保存前看不到具体匹配清单 | 可能保存出含大量误伤的分组，污染下游分析 |
| 无明细下钻入口 | 发现可疑匹配后无法即时核实，被迫切换页面反查 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 每个关键词的股数口径 | 该关键词**单独**匹配的去重股票数 | 直观、可解释、计算确定；管理员关心的是"这个词能捞到什么"，而非净贡献 | 净贡献股数（扣减与其他关键词重叠部分）：语义模糊、计算依赖全量交集、无业务价值 |
| 明细列表粒度 | 一行一条 = 股票代码 + 股票名称 + 股东名称 | 一只股票可能被多个匹配股东持有，按股东展开才能完整呈现"谁在持有"，符合"明细"语义 | 按股票聚合（股东名合并成一列）：无法分行核对每个股东，丢失核验关键信息 |
| 明细触发方式 | 用户点击关键词旁的"查看明细"主动触发 | 单个关键词可能匹配数十至上百只股票，自动加载会造成卡顿和无意义请求 | 编辑时自动加载所有关键词明细：数据量和请求量不可控 |
| 明细查询基准 | 当前编辑框内的关键词草稿（非已保存的关键词） | 预览本就基于草稿实时计算，明细需与预览同口径，保证"所见即所配" | 仅支持已保存分组的关键词：编辑未保存时无法查看，违背"保存前自检"目的 |
| 明细排序与分页 | 按股票代码升序，每页 20 条 | 同股票多股东天然相邻，便于核对；分页应对大数据量 | 按持股比例降序：明细列表不展示比例列，排序依据不可观察，验收困难 |

### 1.4 产品范围

**本期范围**：
- 编辑分组弹窗内，每个关键词旁展示该关键词单独匹配的去重股票数
- 每个关键词支持"查看明细"操作，点开后展示该关键词匹配的明细列表（股票代码 + 股票名称 + 股东名称）
- 明细列表分页展示，按股票代码升序
- 保留现有"所有关键词合并匹配总股数"预览（作为整体参考，与各关键词股数并存）

**明确不做**：
- 分组列表表格行级的"查看明细"（本期仅限编辑弹窗内）
- 关键词质量评分、误伤高亮等智能建议
- 明细数据导出（表格类文件）
- 用户侧股东分析面板的明细展示改造

## 第二部分：用户旅程和用户故事

### 2.1 核心用户旅程

```text
管理员进入"股东监控组管理"页面
  → 点击某分组的"编辑"按钮，打开编辑弹窗
  → 弹窗加载后，每个关键词旁显示"该关键词匹配 N 只股票"
    （与底部"合并总数"并存）
  → 管理员发现某个关键词匹配数异常（偏多/偏少）
  → 点击该关键词旁的"查看明细"
  → 在弹窗内展开该关键词的明细列表（股票代码 + 股票名称 + 股东名称，按股票代码升序）
  → 管理员核对后：
      - 若误伤多 → 删除或修改该关键词，明细与股数实时刷新
      - 若符合预期 → 继续编辑其他关键词或保存
  → 点击保存，分组生效

异常旅程：
- 明细加载失败 → 明细区显示错误提示与"重试"按钮，不影响关键词编辑和分组保存
- 关键词为空 → 该关键词不显示股数与"查看明细"，合并总数按剩余非空关键词计算
- 明细数据量较大 → 列表分页，可翻页查看
```

### 2.2 用户故事

**核心用户故事**：
- US-01：作为管理员，我希望编辑分组时能看到每个关键词分别匹配多少只股票，以便快速定位贡献异常的关键词，而不是只看一个合并总数。
- US-02：作为管理员，我希望能即时查看某个关键词匹配到的具体股票和股东，以便在保存前判断该关键词是否误伤过多，避免保存出噪音分组。
- US-03：作为管理员，我希望修改关键词后匹配股数和明细能自动刷新，以便所见即所配，无需手动刷新。

**延伸用户故事**：
- US-04：作为管理员，我希望明细按股票代码升序排列且同股票多股东相邻，以便集中核对同一只股票的多个匹配股东。
- US-05：作为管理员，我希望明细加载失败时不影响我继续编辑和保存分组，以便预览功能故障不阻塞主流程。

说明：
- 每个关键词行追加"X只"标签（该关键词单独匹配的去重股数）和"查看明细"入口
- 明细在弹窗内就地展开，不离开编辑上下文，避免打断编辑思路
- 底部保留"合并匹配总数"，与各关键词股数并存，便于对照（合并数因跨关键词去重，通常 ≤ 各关键词股数之和）

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
|------|---------|-----------|
| 关键词为空 | 该行不显示股数与"查看明细" | 输入关键词 |
| 股数计算中 | "X只"位置显示加载指示 | 等待 |
| 股数计算完成 | 显示"N只" | 可点击"查看明细" |
| 股数为 0 | 显示"0只"，"查看明细"置灰 | 修改或删除关键词 |
| 明细未展开 | 显示"查看明细 ▾" | 点击展开 |
| 明细加载中 | 明细区显示加载指示 | 等待 |
| 明细加载失败 | 明细区显示错误提示 + 重试 | 点击重试或忽略 |
| 明细已展开 | 列表 + 分页 | 翻页 / 收起 |

### 3.3 业务规则

- **每个关键词的股数**：按"股东名称包含该关键词"单独匹配，按股票去重计数；与"合并总数"独立计算。合并总数因多关键词去重，通常小于或等于各关键词股数之和。
- **股数刷新规则**：关键词内容变化后，输入停止并短暂停顿即重新计算该关键词的股数（与现有合并预览采用同一刷新节奏）。
- **明细内容**：每行展示一条匹配记录 = 股票代码 + 股票名称 + 股东名称，仅这三列固定展示，不含持股比例等其他字段；同一股票被多个匹配股东持有时，按股东分行展示（股票代码与名称重复，股东名称不同）。
- **明细排序**：按股票代码升序，同股票的多个匹配股东相邻排列。
- **明细分页**：默认每页 20 条，支持上下翻页。
- **明细口径**：明细基于"当前编辑框内"的关键词内容实时查询，与是否已保存无关。
- **空关键词**：不参与股数计算、不显示明细入口。
- **降级规则**：股数或明细查询失败时，对应区域显示错误提示，但不阻塞关键词编辑和分组保存（预览是辅助功能，不影响保存主流程）。

## 第四部分：验收标准

- **AC-01：每个非空关键词展示单独匹配的去重股票数**
  前置：已存在含至少 2 个关键词的分组，且系统已同步可被这些关键词匹配的十大流通股东数据
  动作：打开该分组的编辑弹窗
  结果：每个关键词旁显示"X只"；X 为仅用该关键词匹配的去重股数；不同关键词的 X 互不影响、互不依赖

- **AC-02：保留所有关键词合并匹配总数**
  前置：同 AC-01
  动作：查看弹窗底部预览区
  结果：仍展示"合并匹配 N 只股票"；N 与各关键词股数之和因去重未必相等

- **AC-03：点击"查看明细"展示该关键词的明细列表**
  前置：某关键词匹配数 > 0
  动作：点击该关键词的"查看明细"
  结果：列表展示股票代码 + 股票名称 + 股东名称三列；列表内容仅为该关键词的匹配结果，不混入其他关键词的匹配

- **AC-04：同一股票被多个匹配股东持有时按股东分行展示**
  前置：某关键词同时匹配同一股票的两个不同股东
  动作：查看该关键词明细
  结果：该股票出现两行，股票代码与名称相同，股东名称不同

- **AC-05：明细按股票代码升序排列，同股票多股东相邻**
  前置：某关键词匹配多条明细
  动作：查看明细列表
  结果：自上而下股票代码不降序；同一股票代码的多行连续相邻

- **AC-06：修改关键词后股数与明细实时刷新**
  前置：编辑弹窗已打开
  动作：修改某关键词内容并停顿
  结果：该关键词的"X只"股数重新计算；若该关键词明细已展开，明细同步刷新为新内容

- **AC-07：预览或明细查询失败均降级且不阻塞编辑与保存**
  前置：关键词匹配股数查询 或 明细查询任一返回错误
  动作：观察对应区域 → 修改其他关键词 → 点击保存
  结果：失败的查询区显示错误提示与重试入口；其他关键词编辑正常；分组可正常保存

- **AC-08：空关键词不显示股数与明细入口**
  前置：编辑弹窗存在未填写的空关键词行
  动作：观察该行
  结果：该行不显示"X只"股数与"查看明细"入口

- **AC-09：关键词匹配数为 0 时查看明细入口置灰**
  前置：某关键词非空，但该关键词单独匹配的股票数为 0
  动作：观察该关键词行
  结果：该行显示"0只"；"查看明细"入口处于不可点击的置灰状态
