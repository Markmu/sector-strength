**非 blocker 代码质量问题（2 项，建议 plan-04 处理）**：

1. **NB-1（is_watched 第二次无条件 UPDATE 语义争议）**：`data_init_index.py` L207-214 有第二个无条件 UPDATE，强制把预置 14 只设为 is_watched=true。注释说明"AC 要求首次同步后 14 只 must be true"。这与 AC-08a "重复同步不重置已关注的 is_watched 标记" 在**用户主动取消关注预置指数**的边缘场景下存在语义冲突——重复 sync 会把用户取消的关注重置回 true。
   - 影响：首次同步行为正确（满足 AC）；仅影响"用户取消关注预置指数后再次 sync"的边缘场景。
   - 建议处理时机：plan-04 关注管理功能实现时，把第二次无条件 UPDATE 改为仅在首次同步（is_watched IS NULL）时执行，或在关注管理 API 中明确"预置指数可被取消关注且不被 sync 重置"。
   - 不构成 blocker：当前 plan-02 范围内首次同步 AC 满足；关注管理是 plan-04 范围。

2. **NB-2（非预置指数 is_watched 为 NULL 而非 False）**：`index_basic` 表 `is_watched` 列在迁移中 `nullable=True` 无 server_default；sync_index_basic 的 pg_insert 不传 is_watched，导致约 1 万条非预置记录 is_watched=NULL（而非 False）。
   - 影响：`_get_watched_codes` 用 `is_watched.is_(True)` 查询，NULL 记录不会被误判为关注，功能正确；但前端展示/查询 API 若用 `is_watched == False` 过滤会漏掉 NULL 记录（plan-03 查询 API 需注意用 `is_watched IS NOT TRUE` 或 `coalesce`）。
   - 建议处理：plan-03 查询 API 设计时用 `is_watched.is_(True)` / `is_watched.is_not(True)` 而非 `== False`；或在迁移加 `server_default=false`。
   - 不构成 blocker：plan-02 内所有查询都用 `.is_(True)`，行为正确。
