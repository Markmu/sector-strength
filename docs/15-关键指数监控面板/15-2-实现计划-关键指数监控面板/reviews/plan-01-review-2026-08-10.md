## 维度 4：实现规格符合度 — 通过

### 4 个数据模型（index_monitor.py）

| 模型 | 规格要求 | 实测 | 符合 |
| --- | --- | --- | --- |
| IndexBasic | ts_code unique + 9 字段 + is_watched default false | ts_code unique=True nullable=False；is_watched=Column(Boolean, default=False) | 是 |
| IndexDaily | uq(trade_date,ts_code) + idx(trade_date) + idx(ts_code,trade_date) | `uq_index_daily_date_code` + `idx_index_daily_date` + `idx_index_daily_code_date` | 是 |
| IndexDailyBasic | uq(trade_date,ts_code) | `uq_index_dailybasic_date_code` | 是 |
| IndexWeight | uq(index_code,con_code,trade_date) + idx(index_code) | `uq_index_weight_code_con_date` + `idx_index_weight_code` | 是（多 1 个 `idx_index_weight_con_code`，见建议项 S-2） |

Numeric 精度全部正确：total_mv/float_mv Numeric(24,2)，total_share Numeric(24,0)，pe_ttm Numeric(10,4)，vol Numeric(20,2) 等，与规格完全一致。

### is_watched 默认值

`Column(Boolean, default=False, comment="是否加入关注清单")` — ADR-2 要求满足。

### 4 个采集方法（tushare_client.py 1336-1573 行）

- `get_index_basic(market=None, ts_code=None)` — 全量拉取，不暴露 name 入参（符合"代理上 name 不生效"风险备注）
- `get_index_daily(ts_code, start_date, end_date)` — date → strftime("%Y%m%d")
- `get_index_dailybasic(ts_code, start_date, end_date)` — 空 DataFrame 返回空列表
- `get_index_weight(index_code, start_date, end_date)` — **参数名为 index_code**（规格关键要求，非 ts_code）

### _execute_with_retry 复用

4 个方法均在 `pro = self._get_pro_api()` 后用 `self._execute_with_retry(_fetch)` 包裹 fetch 闭包，与 `get_sw_index_classify` 范式一致。

"不在范围"（采集服务编排/查询 API/前端）均未越界实现。

## 维度 9：代码审查 — 通过

### 阻塞项（blocker）

无。

### 建议项

**S-1（低，文档）**：`plan-01` 验证命令写的是 `source ../.venv/bin/activate`，但本机 venv 实际在 `server/.venv`，且 `DataSourceFactory` 不会自动 `load_dotenv()`，新会话直接跑会因 `TUSHARE_TOKEN 未配置` 报错。建议后续 plan 的验证命令统一为 `cd server && source .venv/bin/activate && export $(grep -v '^#' ../.env | xargs)` 或在测试脚本顶部加 `load_dotenv()`。不影响本功能正确性。

**S-2（低，超规优化）**：`index_weight` 表实际多了一个 `idx_index_weight_con_code`（按 con_code 索引），规格 §实现规格 #1 只列了 `idx_index_weight_code`。这是合理的下游查询优化（按成分股反查），不阻塞，但属超规格实现。鉴于 plan-01 §风险与边界声明"允许修改的额外文件: 无"是针对文件而非索引，且该索引对 plan-03/plan-04 有益，判定为可接受的建议项。如需严格对齐，可在规格中补一条索引说明。

### 正确性 / 安全

- 字段类型精度与规格一致，无错位
- UniqueConstraint 名称与规格字面一致（uq_index_daily_date_code 等）
- 4 个采集方法均返回 `List[dict]`，NaN → None 处理与 `get_sw_index_classify` 一致
- 无 SQL 注入面（采集方法不拼 SQL，参数走 Tushare SDK）
- 无用户输入直传（采集方法入参由服务层控制）
- 日期校验（start > end 抛 ValueError）已加在 daily/dailybasic/weight，basic 无日期参数故无需
