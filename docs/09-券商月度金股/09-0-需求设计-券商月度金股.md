# 09-0 需求设计：券商月度金股

## 0. 文档说明

**产品核心目标**：让投资者一键看到"全市场券商每月最集中推荐哪些股票"，发现卖方研报共识股，并能从券商维度反查"每家券商本月推了什么"。

**本需求定位**：
- **上期基础**：04 期基金持仓、05 期十大流通股东、08 期基金扎堆分析已构建出"买方机构共识"视角（基金扎堆）和"个股股东结构"视角；站内已具备成熟的 Tushare 同步任务体系（数据管理页手动触发、可取消、带进度回调）。
- **本期做什么**：新增"券商每月荐股"模块，按月同步 Tushare 券商金股数据（券商每月金股接口），提供股票维度（被多少家券商推荐排行）与券商维度（每家券商本月推荐清单）双视图，支持月份切换。
- **阶段定位**：补充"卖方共识"这一与基金扎堆（买方共识）对称互补的全新视角，让用户从买卖双方双向印证个股的市场关注度。

**相关文档**：
- 04 需求设计：A 股基金持仓分析
- 08 需求设计：基金扎堆股票分析（买方共识视角，与本期的卖方共识视角对称）

## 第一部分 需求分析与确认

### 1.1 项目背景

站内已有的"基金扎堆分析"回答了**买方机构**（基金）最扎堆看好哪些股票，但缺少与之对称的**卖方机构**（券商）视角。个人投资者在做决策时，常会关注"各大券商研究所每月联合推荐的金股"——这是市场公认的卖方选股风向标。当一只股票同时被多家头部券商推荐，往往意味着卖方研究的强共识。

目前用户要获取这个信号，只能去各家券商公众号、研报平台逐家翻看每月金股清单，然后人工脑算"这只被 8 家券商推、那只被 3 家推"，完全无法形成全市场的卖方共识排名。更关键的是两个观察盲区：

1. **看不到集中度排行**：无法快速回答"本月被最多券商推荐的是哪些股票"，发现不了卖方共识股。
2. **缺券商视角反查**：用户不仅想知道"哪些股票被集中推荐"，有时也想直接看"我关注的某家券商本月推了什么"，目前无任何入口。

**本期目标（一句话）**：让用户能打开一个"券商每月荐股"页面，默认看到本月被最多券商推荐的股票排行，一键切换到券商分组视图查看每家券商的本月金股清单，并支持切换历史月份。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|---|---|
| 没有"被多少家券商推荐"的聚合排行 | 只能逐家券商翻看金股清单人工脑算，发现不了卖方共识股，更看不出共识强弱（多家共推 vs 单家推荐混在一起） |
| 缺券商维度反查 | 想看"我关注的某家券商本月推了什么"无入口，只能外站搜索，且外站口径各异、更新滞后 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---|---|---|---|
| 数据来源 | Tushare 券商每月金股接口（券商推荐数据） | 该接口聚合了各券商每月披露的金股清单与推荐理由，免去逐家爬取；与站内已用 Tushare 数据源统一 | 逐家券商官网/公众号爬取（维护成本高、口径不一） |
| 同步触发方式 | 复用现有异步任务体系，在数据管理页新增"券商月度金股同步"任务，管理员手动触发、可取消 | 与基金持仓同步、十大流通股东同步完全一致，用户心智与运维流程统一；金股数据更新频率低（每月），无需定时 | 定时自动同步（首版无需，手动触发可控）、两者都要（首版过重） |
| 同步粒度 | 按"月份"参数整月拉取，同一月份为覆盖式更新（刷新而非堆积）。月份参数 YYYYMM 映射为该月**最后一个交易日**的金股快照（券商金股按月发布，月末快照为该月最终推荐清单；不逐交易日拉取、不做全月合并） | 与现有同步服务"覆盖式更新"模式一致；金股按月发布，整月为天然单位；取月末快照避免全月多次重复抓取同一推荐 | 逐券商/逐股票拉取（接口支持按交易日期整批返回，无需拆分）；逐交易日拉全月后合并（重复抓取、数据冗余） |
| 月份默认值 | 默认展示"最新已同步月份"，"最新"=已同步月份中 YYYYMM 值最大者（按月份值，不按同步时间） | 覆盖式更新历史月份时不会改变默认月份指向；月份值最大即最近一期金股，符合用户直觉 | 按同步时间（覆盖重同步旧月会把默认月份带偏到旧月） |
| 默认展示视角 | 顶部默认股票维度（被推荐券商家数降序），提供切换到券商分组的视图 | 双维度并列：股票维度解决"卖方共识排行"主诉求，券商维度解决"反查某家券商"次诉求；默认股票维度贴合"发现共识"主旅程 | 仅股票维度（缺反查）、仅券商维度（缺排行） |
| 推荐家数口径 | 同一月份内，对同一股票去重统计"推荐它的不同券商数量"作为主排序指标 | 券商金股接口可能对同一股票返回多条记录（不同券商），按券商去重计数才反映"独立卖方共识广度" | 按原始记录条数计数（同一券商多条会重复计数虚高） |
| 时间维度 | 提供月份选择器，默认最新已同步月份，可切换历史月份 | 金股按月发布，用户有回顾历史月份诉求；默认最新满足"看当下"主诉求 | 仅展示最新（无法回顾）、自动环比（首版过重） |
| 菜单位置 | 在侧边栏"基金扎堆分析"之后新增"券商每月荐股"菜单，与现有分析页平级 | 聚焦"卖方共识"独立视角，与买方共识（基金扎堆）并列，导航清晰 | 嵌入基金扎堆分析页（视角混淆） |
| 与现有分析的关系 | 并列新视角：基金扎堆是"买方共识"，本期是"卖方共识"；二者数据独立，互不下钻 | 买卖双方共识互补，但首版不打通联动，保持各自清晰 | 首版即做买卖方交叉推荐（首版过重，待验证） |

### 1.4 产品范围

**本期范围（必须交付）**：

- **数据同步**：在数据管理页新增"券商月度金股同步"任务，管理员可指定月份（YYYYMM 格式）触发同步，复用异步任务体系（进度回调、可取消、并发保护）。
- **股票维度排行**：按"被多少家券商推荐"降序排列的股票列表，每行展示股票代码、名称、所属行业、推荐券商家数、推荐券商（折叠展示前 3 家+省略，完整列表与推荐理由通过行展开查看）；按分页加载。
- **券商维度反查**：切换到券商分组视图，按券商列出本月推荐的所有股票及推荐理由；按分页加载。
- **月份选择**：提供月份选择器（界面显示 YYYY-MM 格式，对应数据为 YYYYMM 月度参数），默认最新已同步月份，可切换查看历史月份；月份列表取自已同步成功的月份。
- **侧边栏菜单**：新增"券商每月荐股"菜单项，进入券商金股分析页。

**明确不做**：

- 券商金股的推荐收益/涨跌幅跟踪（需接入行情数据，首版不做）
- 买卖方共识交叉推荐（如"同时被基金扎堆和券商推荐"的联动分析）
- 金股的多期走势曲线与环比变化（首版仅单月展示，不做环比）
- 行业分布聚合与可视化（首版不提供按行业聚合的分布区；个股的行业字段仍展示，但不做行业维度的统计聚合）
- 用户自定义券商池监控与推送
- 推荐理由的 NLP 摘要与情感分析

## 第二部分 用户旅程和用户故事

### 2.1 核心用户旅程

**主旅程：用户发现"卖方共识股"**

```
[1. 用户从侧边栏进入"券商每月荐股"页面]
   ↓
[2. 页面默认展示"最新已同步月份 · 股票维度"的推荐排行]
   ↓
[3. 用户看到榜首股票：本月被 12 家券商共同推荐]
   ↓
[4. 用户点击该股票行，展开查看是哪 12 家券商在推荐及各自推荐理由]
   ↓
[5. 用户据此判断卖方研究共识方向，辅助持仓决策]
```

**主旅程：用户反查某家券商本月金股**

```
[1. 用户在页面切换视图为"券商维度"]
   ↓
[2. 页面按券商分组列出本月有推荐的所有券商]
   ↓
[3. 用户找到自己关注的券商（如"中信证券"），展开其本月推荐清单]
   ↓
[4. 用户查看该券商本月推荐的股票及推荐理由]
```

**主旅程：用户回顾历史月份**

```
[1. 用户在月份选择器切换到上月（或更早月份）]
   ↓
[2. 页面清空搜索词、保持当前视图（股票/券商），按所选月份重新加载数据并回到第 1 页]
   ↓
[3. 用户回顾历史月份的卖方共识，与当前月份主观对比]
```

**主旅程：管理员同步券商金股**

```
[1. 管理员进入数据管理页，选择某月份（YYYYMM）触发"券商月度金股同步"]
   ↓
[2. 系统创建异步任务，按该月最后一个交易日的快照拉取券商金股数据]
   ↓
[3. 任务列表实时显示进度与日志，管理员可中途取消]
   ↓
[4. 同步成功后该月份数据可被分析页查询；重复触发同一月份为覆盖式刷新]
```

**异常旅程**：

- **搜索无结果**：用户在搜索框输入关键词后无匹配，表格区显示"未找到匹配结果，请调整搜索词"；清空搜索词即恢复完整列表。
- **金股数据从未同步**：页面展示空状态"暂无券商金股数据，请联系管理员同步"，不展示错误堆栈。
- **所选月份无数据**：若用户切换到某个尚未同步的月份（理论上月份选择器仅展示已同步月份，但存在数据被清空等边界情况），页面提示"所选月份暂无数据"。
- **同步任务进行中**：数据管理页触发同步时，若已有同类型任务运行中，提示"已有券商金股同步任务正在运行，请等待完成"，避免并发。
- **同步失败**：任务详情页记录失败原因（如接口权限不足、网络超时）并标记失败，不影响已同步的历史数据展示；管理员可重试。

### 2.2 用户故事

**核心用户故事**：

- **US-01**：作为个人投资者，我希望看到一个"被最多券商推荐"的股票排行榜，以便快速发现当前卖方研究最集中看好的共识股。
- **US-02**：作为个人投资者，我希望能切换到券商分组视图，查看某家券商本月推荐了哪些股票及理由，以便跟踪我关注的券商的研究方向。
- **US-03**：作为个人投资者，我希望能切换历史月份，回顾过去的卖方共识变化，以便对比当下与历史。
- **US-04**：作为管理员，我希望能在数据管理页手动触发券商金股的月度同步并查看进度，以便按需更新数据。

### 3.3 业务规则

- **排序规则**：股票维度默认按"推荐券商家数"降序；家数相同时按股票代码升序作为次级排序。券商维度默认按"本月推荐股票数"降序，相同时按券商名称排序。
- **推荐家数口径（去重键）**：同一月份内，对同一股票按**券商名称**去重统计推荐它的不同券商数量（券商金股接口可能对同一股票返回多条记录，同一券商对同一股票若有多条记录，按券商名称归并为 1 家）。该去重后的家数即主排序指标"推荐券商家数"。
- **同券商多理由归并**：同一券商对同一股票若存在多条推荐理由记录，合并为 1 家计数；展开查看时该券商展示其全部理由（多条理由分行或以分隔符拼接展示），不丢弃任何理由文本。
- **搜索规则**：股票维度支持按股票代码（含后缀）或名称搜索；券商维度支持按券商名称搜索；代码按前缀匹配、名称按包含匹配、不区分大小写；无匹配时显示"未找到匹配结果，请调整搜索词"，清空恢复完整列表。搜索为**服务端全量重查**（对当前月份、当前视图的全部数据过滤，而非仅过滤当前页），每次输入/清空搜索词后**回到第 1 页**重新分页，"共 N"按新结果重新计算。
- **视图切换规则**：默认选中"股票维度"；切换视图**清空当前搜索词**、保持当前所选月份、回到第 1 页；切换状态与所选月份在当次浏览会话内保持。
- **月份选择规则**：月份选择器仅展示已同步成功的月份，界面以 YYYY-MM 格式显示、底层对应 YYYYMM 月度参数；默认选中**最新已同步月份（已同步月份中 YYYYMM 值最大者，不按同步时间）**；切换月份后**清空当前搜索词**、保持当前视图（股票/券商）、两个视图均按新月份重新加载并回到第 1 页。
- **分页规则**：股票维度与券商维度均分页加载，默认每页 20 条；股票维度"共 N 只"指当前月份、当前搜索条件下符合的股票总数（非当前页条数）；券商维度"共 N 家"同理指符合条件的券商总数；分页在当前视图的排序与搜索条件下生效，切换视图或月份后回到第 1 页；当总数 ≤ 单页上限时分页器隐藏（仅展示"共 N 只/家"总数），不再显示页码控件。
- **展示与展开规则**：股票维度每行折叠态展示"推荐券商"列，固定显示前 3 家券商名称，超过 3 家以"+X 家"省略；点击该行的展开控件，展开后按券商分行展示全部推荐券商及其各自推荐理由。券商维度每家券商为一个可折叠分组，折叠态展示券商名称与本月推荐股票数，展开后展示其本月推荐的股票代码、名称及推荐理由。
- **展开加载机制**：两个维度的展开机制不同——股票维度展开所需数据（该股全部推荐券商及理由）数据量小，随列表数据一并返回，无需二次请求；券商维度展开（该券商本月全部推荐股票明细+理由）数据量较大，采用**懒加载**：点击展开时单独请求该券商明细，展开期间显示"展开加载中"骨架，加载失败显示"加载失败，请重试"并可重新展开。展开项数据为空时展示"暂无推荐理由"，不阻断其他行。
- **行业字段规则**：每只股票的行业取自站内行业板块体系，与其他分析页口径一致；若某股票无行业归类数据，该股票行业列显示"—"，不影响其在榜单中的展示与排序。
- **同步任务规则**：同步以"月份"为单位整月拉取，同一月份为覆盖式更新（刷新而非堆积）；触发时检查同类型任务并发保护；任务支持进度展示与取消。
- **单位与精度规则**：推荐券商家数为整数（按券商名称去重后口径）。

## 第四部分 验收标准

- **AC-01：侧边栏菜单与页面入口**
  前置：无。
  动作：用户登录后查看侧边栏。
  结果：侧边栏在"基金扎堆分析"之后出现"券商每月荐股"菜单项；点击后进入券商金股分析页。

- **AC-02：股票维度排行榜展示**
  前置：管理员已同步至少一个月的券商金股数据。
  动作：用户进入"券商每月荐股"页面。
  结果：页面默认展示"股票维度 · 最新已同步月份"的卖方共识排行榜，按推荐券商家数（按券商名称去重口径）降序排列；每行折叠态展示股票代码、名称、所属行业（无行业显示"—"）、推荐券商家数、推荐券商（固定前 3 家，超过以"+X 家"省略）；榜单仅包含当月至少被 1 家券商推荐的股票。

- **AC-03：股票维度展开推荐详情**
  前置：股票维度排行榜已加载。
  动作：用户点击某只股票行的"展开"控件。
  结果：展开后按券商分行展示该股票当月全部推荐券商名称及各自推荐理由；同一券商若有多条理由，全部展示不丢弃；再次点击收起。

- **AC-04：券商维度反查与展开**
  前置：页面已加载。
  动作：用户将视图切换为"券商维度"，并点击某券商分组的展开控件。
  结果：页面按券商分组列出本月有推荐的所有券商，每组折叠态展示券商名称与本月推荐股票数；展开某券商后展示其本月推荐的股票代码、名称及推荐理由；视图切换不改变当前所选月份。

- **AC-05：月份切换**
  前置：已同步多于一个月的数据。
  动作：用户在月份选择器切换到另一历史月份。
  结果：保持当前视图（股票/券商），按所选月份重新加载数据并回到第 1 页；月份选择器仅含已同步成功的月份，界面以 YYYY-MM 显示。

- **AC-06：分页加载**
  前置：股票维度或券商维度当月数据条数超过单页上限（20）。
  动作：用户点击分页器的"下一页"或某一页码。
  结果：表格加载对应页的数据，保持当前排序与搜索条件；"共 N 只/共 N 家"展示的是当前月份、当前搜索条件下的总数（非当前页条数）；当总数 ≤ 单页上限时分页器隐藏；切换视图或月份后自动回到第 1 页。

- **AC-07：次级排序**
  前置：股票维度排行榜存在至少两只"推荐券商家数"相同的股票（或券商维度存在两家"本月推荐股票数"相同的券商）。
  动作：用户查看这些并列项的顺序。
  结果：股票维度家数相同时按股票代码升序排列；券商维度推荐股票数相同时按券商名称排序。

- **AC-08：数据同步任务**
  前置：用户为管理员，进入数据管理页。
  动作：管理员选择某月份（YYYYMM）触发"券商月度金股同步"任务。
  结果：系统创建异步同步任务，按该月最后一个交易日的快照拉取数据，任务列表显示进度与日志；同步成功后该月份数据可被分析页查询；重复触发同一月份为覆盖式刷新，不产生重复堆积；已有同类型任务运行中时拒绝并发并提示；任务支持取消。

- **AC-09：数据从未同步的空状态**
  前置：券商金股数据从未同步过。
  动作：用户进入券商金股分析页。
  结果：页面展示空状态提示"暂无券商金股数据，请联系管理员同步"，不展示任何错误堆栈。

- **AC-10：默认月份**
  前置：已同步多于一个月的数据。
  动作：用户首次进入"券商每月荐股"页面。
  结果：月份选择器默认选中"已同步月份中 YYYYMM 值最大者"，且不受各月同步先后时间影响。

- **AC-11：股票维度搜索**
  前置：股票维度排行榜已加载。
  动作：用户在搜索框输入某只股票的代码或名称。
  结果：搜索对当前月份全量数据做服务端重查（非仅过滤当前页），命中时表格仅保留匹配股票并自动回到第 1 页，"共 N 只"按新结果重新计算；无匹配时显示"未找到匹配结果，请调整搜索词"；清空搜索词后恢复完整榜单并回到第 1 页。

- **AC-12：券商维度搜索**
  前置：页面已切换到券商维度。
  动作：用户在搜索框输入某券商名称。
  结果：搜索对当前月份全量数据做服务端重查，命中时分组列表仅保留匹配券商并回到第 1 页；无匹配时显示"未找到匹配结果，请调整搜索词"；清空搜索词后恢复完整券商列表并回到第 1 页。

- **AC-13：券商维度展开懒加载**
  前置：已切换到券商维度并展示分组列表。
  动作：用户点击某券商分组的展开控件。
  结果：展开期间显示"展开加载中"骨架，单独请求该券商本月推荐明细后展示股票代码、名称及推荐理由；加载失败显示"加载失败，请重试"且可重新展开；明细为空时显示"暂无推荐理由"。

- **AC-14：切换视图/月份时的搜索词与分页重置**
  前置：用户在股票维度搜索"茅台"并停留在某页。
  动作：用户切换到券商维度，或切换到另一历史月份。
  结果：当前搜索词被清空、回到第 1 页、按新视图/新月份重新加载完整列表。
